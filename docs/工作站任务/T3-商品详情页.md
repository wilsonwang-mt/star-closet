- “2D 试穿放在商品详情页的‘上身效果’里：用户本人出现在不同场景图里，穿着这件商品。”

## 功能

1. **`/item/[id]` 详情页**
   - 首屏：商品大图（可以复用衣橱页的电影感场景背景），名称、价格、颜色、材质、尺码、所属衣橱（链接回衣橱页）、购买按钮（沿用目录里的 `buy_url` 和 `buy_label`）。
   - 下方是“这件出现在哪些搭配里”：列出包含这件单品的搭配卡片，链接到 `/outfit/[id]`。
2. **“上身效果”区块**：横向画廊，每张是 3:4 竖图卡片。数据来源按优先级：
   - **用户本人**：已登录、已有正面照（试穿流程里上传的 `avatar_photo` slot=front）、已勾选试穿同意（`tryon_consent`）、并且有 `FAL_KEY`。点击“生成我的上身效果”后生成 2 张场景图，标题为“你的上身效果”。
   - **演示模特**：没有本人结果时，读 `app/public/demo/manifest.json`（T2 的产出），标题为“模特上身”，如实写明是模特。
   - 两者都没有时：已登录的用户显示生成入口，未登录的用户点击后去登录页。
3. **场景图生成**（`POST /api/scene`，body `{ itemId }`）
   - 用 `fal-ai/nano-banana-pro/edit`，输入用户正面照、商品图和场景描述。场景按单品风格从 T2 那组场景里选 2 个。
   - 要求商品的颜色、款式、材质和商品图一致，人物长相保持本人不变。
   - 结果存进私有存储 `<userId>/avatars/scene-<id>.jpg`。现有存储的 key 规则只允许 `photos|avatars`，所以沿用 `avatars/`，这样一键删除时也会一起删掉。
   - 新表 `scene_render` 字段：id、user_id（外键关联 user，级联删除）、item_id、scene_id、status、image_key、video_key、error、created_at。
   - 同一用户同一件单品只保留最新一组结果。一键删除 3D 形象时要一起清掉，需要在 `lib/avatar/service.ts` 的 `deleteAll` 里加一行调用。这是唯一允许改动的试穿和形象相关文件，只加这一行。
4. **Live 动态**
   - 用户本人的场景图生成后，在后台对每张发起 image-to-video：用 fal 的 queue 接口，提交后轮询结果，生成 3 到 4 秒、动作细微、无声的视频，存为 `<userId>/avatars/scene-<id>.mp4`。
   - 视频没生成好之前，卡片照样能悬停或长按，这时用纯前端效果代替：轻微推镜加光影扫过，不显示 LIVE 标。视频就绪后才显示 LIVE 标并播放真视频。
   - 演示模特的卡片直接用 manifest 里的 `live` 视频。
5. **`<LivePhoto>` 组件**（`app/components/live/`）
   - 桌面端悬停约 150ms 后开始播放；手机端长按约 300ms 开始，并配一次轻震动（`navigator.vibrate` 可用时）。松开或移出后回到静态图。
   - 实况照片的手感：按下瞬间图片轻微放大到约 1.04 倍，同时略微虚化后清晰，视频从第一帧淡入；左上角 LIVE 标的圆环做一次描边动画。
   - 视频不自动下载：首次悬停或长按时才加载。`prefers-reduced-motion` 开启时只显示静态图，不播放。
   - 只动 transform 和 opacity，保证 60fps。
6. **入口**：衣橱页、搭配页、改编结果里的单品缩略图和名称都可以点进 `/item/[id]`。改编结果里的替换下拉等现有交互不能受影响。
