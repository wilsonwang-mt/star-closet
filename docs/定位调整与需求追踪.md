# v0.3 定位调整与需求追踪

版本：0.3 · 2026-10-15（Asia/Shanghai，UTC+08，与新加坡同一时刻）。
状态：已对照实际落盘的 v0.3 主文档、细化方案与 26 页静态 Slides；运行检查与发布结果另见[评审记录](评审记录.md)和[交付记录](交付记录.md)。文档覆盖不等于应用实现。

本轮从“明星衣橱及服饰展示”扩大为 **AI 辅助的策展衣橱、社交发现、个人试衣与选购平台**。
下文 D 编号沿用[决策记录](决策记录.md)；这里记录整理日期，不推定历史消息的发送时间。
“用户明确提出”指产品愿景与本轮规划范围，不代表已批准应用编码、收费参数或首次上线范围，更不代表已经实现。

## 1. 继承与替代

继续保留浅弧首页、中央最大正对、两侧露出、头像姓名风格介绍、暗色玻璃、复杂光影、手机操作与横屏提醒。
核心可选服饰仍须有完整真实可旋转模型；个人化身与试穿不能取代该要求。

旧文档把试穿、个人形象、账号相关能力和收藏列为未提出或不纳入整体需求的结论，已被最新要求替代。
这些能力进入完整平台规划；具体首版阶段可以建议收敛，但不能借 MVP 排期从愿景中删除。
旧研究原文保留为历史快照，当前入口与活跃文档必须说明其适用时点。

## 3. 必须分开的对象

以下是为落实新需求提出的信息规则，具体界面和实现仍属建议。

| 对象 | 作用 | 与其他对象的边界 |
| --- | --- | --- |
| 公共策展衣橱 | 经过适用审核后供发现、浏览及选品 | owner 可为个人或组织；发现标签不是 owner；主题人物不自动是合作方或收益人 |
| 点赞 | 表达偏好及形成真实统计 | 不等于收藏、购买、拥有实物或购买内容门票 |
| 收藏 | 保存感兴趣的衣橱或单品引用 | 不自动变为本人已拥有物；内容撤回后需有准确状态 |
| 个人试衣间 | 暂存候选、搭配、比较和试穿状态 | 是购物前工作区，不代表锁库存、报价有效或产生订单 |
| 私密个人衣橱 | 持续保存个人衣物与搭配记录 | 仅本人可见，不提供邀请、团队或分享访问；本人拥有、收藏意向及试穿记录分别表示 |
| 本人三维化身 | 个人形象与试穿所需身体表示 | 默认仅本人端可见，原始素材、化身、尺寸与衍生图分别受控；必要处理授权不等于团队浏览权限 |
| 购物袋与实物结算 | 选定真实 SKU、数量、供给与报价后成交 | 试衣间转入须重新核实规格、价格、库存与配送；试穿不保证合身 |
| 数字门票与访问权益 | 购买特定内容的许可访问 | 不等于商品所有权、实物交易或隐私数据访问权；一次票与订阅不得混称 |

### 公共发现分类与主体分开

建议独立记录：账户主体、衣橱 owner、团队角色、人物／品牌关系、发现标签、审核状态和可见范围。
同一衣橱可同时属于某人物、品牌主题及某种风格；“全部”结果按稳定衣橱 ID 去重。
进入某个发现入口不改变内容归属，也不能赋予官方合作徽章或发布权限。
审核通过的个人公共衣橱，不等于用户私密空间已经同意公开；公共发布须为独立提交对象，不修改个人私密空间的仅本人访问规则。

### 建橱 Agent 与搭配助手分开

建橱 Agent 处理创作者提供的素材、结构化资料、陈列和发布草稿；搭配助手处理消费者的检索、比较和试穿诉求。
两者即使共用模型服务，也必须分别检查身份、工具权限、资料来源及可调用操作。
AI 生成建议不能直接发布、收费、替换商品事实或读取其他用户的个人试衣资料。
照片、视频和语音不自动证明本人授权、商品背面、尺码、明星归属或销售资格。

## 4. 四类业务账本与分成核对

为与商业文档一致，本轮采用以下四类业务账本口径；具体费率、周期和资金流仍待决定。
四类业务账本不替代底层订单、付款、退款、结算和权益事件记录。

| 业务账本 | 对应收费或收益 | 核对重点 |
| --- | --- | --- |
| B2B 入驻服务 | 建橱／维护等明确服务，广告赞助为独立子项 | 服务交付、费用与退款，不能默认同时收另一方案费用 |
| C2B 数字门票 | 粉丝购买指定授权内容访问 | 净票款、平台／创作者份额、访问期限、退款与权益撤回 |
| C 端私密衣橱服务（一次／周期待定） | 个人空间的约定服务权益 | 容量／功能、使用期限、取消与到期；若采用订阅再确定续费规则，不默认包含他人的付费内容 |
| 商品成交归因分成 | 合同约定有效成交对应的佣金池 | 净成交与退款、唯一总池、受益方、分配和实际结算 |

“入驻费”和“免入驻费按成交分池”是两条待比较路线；混合收费须另行同意，且说明分别购买了什么服务。
用户已提出个人空间付费，尚未选择周期订阅或一次容量解锁；订阅测算仅为候选，一次收费也不意味着永久、无限存储或计算。
GMV、代收货款、供应商应付、创作者应付、平台留存收入和利润不得混用。
同一订单或商品行的创作者分配只能出自同一个适用合同收益池，不对多个来源分别计算一整份佣金。
净成交扣除哪些折扣、退款、税费、运费与支付费用，需按合同明确；本矩阵不擅自决定统一公式。
退款、拒付、取消和部分退货应能冲回关联收益、应付及访问权益，保留审计，不覆盖原始记录。
买了衣服、付了个人空间费或买了内容门票，不相互推导出额外权益。

## 5. 准确度、隐私与 AI 权限核对

### 三类真实能力分别验收

1. **服饰三维观察**：完整模型正侧背、材质与具体服饰表示范围，继续沿用已确认要求。
2. **本人三维化身**：个人身份与身体表示、尺度和形体误差、采集条件及失败人群需单独验证。
3. **穿着效果与适配**：所选版型、尺码、身体和面料如何对应；视觉好看不自动证明合身或真实布料仿真。

建模耗时、交互渲染与试穿响应分别记录，不能用实时显示已有模型证明实时重建成功。
可比较二维视觉试穿作为明确标注的实验，但不能计作准确个人三维或完整三维试穿达标。
不支持的素材、服饰或变体需说明；准确度和实时指标未定不等于删除该目标。

### 数据与访问规则建议

- 原始照片／视频／语音、体型资料、化身、试穿结果、提示词与衍生索引建立可追溯关联。
- 消费者私密衣橱仅本人可见，公开建橱团队的权限不继承到该空间；本人媒体和化身也不向创作者或团队成员开放。必要处理按用途授权，不等于可浏览该用户资产。
- 未经明确选择，不公开本人形象、不用于其他用户推荐或模型训练。
- 免费额度耗尽、订阅取消或门票退款，不得自动公开采集素材和化身；数据保留／导出／删除流程需提前说明。
- 付费内容访问与个人隐私数据访问分别授权；粉丝付费不能读取个人体型、证据原件或用户私密文件。
- 搜索、AI 检索、推荐、缓存与分享链接同样检查发布态、受众和权益，不能只遮住页面正文。
- 删除操作须先明确范围：清理原始媒体可按本人选择保留仍获授权的化身；删除指定形象版本处理相应结果；撤回相关用途或全部删除则清理相应派生链。不能把清理原片默认扩大为删除其他收藏或仍获准保留的形象。
- 内容撤回或指定范围删除应传播至索引、向量表示、缓存、引用和可控制的衍生结果；第三方处理和备份的可执行范围需确认。
- 删除个人形象与依法保留的最小交易记录分开处理；不以财务留痕为由长期保留全部采集素材。
- 语音中的意图和事实需可检查、更正，不能将外部素材中的文本当成系统授权。
