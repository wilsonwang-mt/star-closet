# 商品目录模板 · 第一位主理人

2026-10-15。对应 [项目Owner评审与推进方案](../项目Owner评审与推进方案.md) §3.1 核心层：时尚顾问（第一位主理人）策展的 6–8 套搭配、30–40 件单品。

**状态：数据模板，供顾问今晚填写。** 应用编码尚未授权；授权后，本模板的字段会原样转成静态 JSON，供“一句话改约束 → AI 在目录内改编整套”使用。AI 只会从这份目录里挑单品，所以字段写得越准，改编越可信。

## 1. 字段定义

字段名用英文小写加下划线（转 JSON 时直接用）；说明用中文。“必填”为空时这一行不能用。

### 1.1 搭配（outfit）

| 字段 | 必填 | 说明 | 示例 |
| --- | --- | --- | --- |
| `outfit_id` | 是 | 固定格式 `O01`–`O08`，填好后不再改 | `O01` |
| `name` | 是 | 搭配名称，10 字左右 | `占位：周末咖啡馆` |
| `style_note` | 是 | 风格说明，1–3 句：这套想表达什么、为什么这样配。AI 改编时会参考它保留原味 | 见 §2 |
| `occasion_tags` | 是 | 场合标签，可多个，优先从下方常用值选 | `["约会", "周末休闲"]` |
| `curator` | 是 | 主理人代号，不写真名或联系方式 | `curator_01` |
| `item_ids` | 是 | 这套包含的单品编号，按“上装→下装→外套→鞋→包→配饰”排列；一套通常 4–6 件 | `["I001", "I002"]` |

场合标签常用值：`通勤`、`约会`、`周末休闲`、`婚礼宾客`、`户外婚礼`、`聚会`、`旅行`、`面试`、`运动休闲`。需要新值可以直接写，保持简短。

### 1.2 单品（item）

| 字段 | 必填 | 说明 | 示例 |
| --- | --- | --- | --- |
| `item_id` | 是 | 固定格式 `I001`–`I040`；同一件单品可被多套搭配引用，只录一次 | `I001` |
| `name` | 是 | 单品名称，写清款式，例如“米白圆领针织开衫” | `占位：米白针织开衫` |
| `category` | 是 | 只能是 `上装`、`下装`、`外套`、`鞋`、`包`、`配饰` 之一；连衣裙记为 `上装` 并在 `tags` 加 `连衣裙` | `上装` |
| `color` | 是 | 主色，中文常用色名；有两种主色用“/”分隔 | `米白` |
| `price` | 是 | 纯数字，不带货币符号、不写“约” | `299` |
| `currency` | 是 | 货币代码。默认 `CNY`（按中文市场的评审假设，币种尚待发起人确认） | `CNY` |
| `price_checked_at` | 建议 | 核对价格的日期，`YYYY-MM-DD`。公开价格会变，演示前需复核 | `2026-10-15` |
| `buy_url` | 是 | 公开商品页链接，见 §4.3 | `https://example.com/item/001` |
| `image` | 否 | 图片链接或文件名；没有合规图片就留空，不影响这一行可用 | `I001.jpg` |
| `image_rights` | 有图时必填 | 只能是 `自有拍摄` 或 `商家书面授权`；无图时留空 | `自有拍摄` |
| `image_rights_note` | 有图时必填 | 一句话说明：谁拍的 / 谁、何时、以什么方式授权 | `顾问本人 2026-10-15 平铺拍摄` |
| `size_note` | 否 | 商品本身的尺码说明，例如 `S–XL`、`均码`、`偏大一码，按商家尺码表`。不写任何人的身体数据 | `均码，偏宽松` |
| `tags` | 否 | 特征标签，帮助 AI 按约束替换，例如 `平底`、`高跟`、`秋冬`、`针织`、`可机洗` | `["针织", "秋冬"]` |

## 4. 填写要求

### 4.1 数量与搭配结构

- 搭配 6–8 套，单品 30–40 件。
- 每套 4–6 件，至少包含上装、下装（或连衣裙）和鞋。
- 鼓励单品在不同搭配间复用，但每类至少准备 2–3 个可替换的备选（尤其是鞋和包），否则 AI 收到“换成平底鞋”“预算 800 以内”这类要求时没有东西可换。
- 价格覆盖一个范围：同一类别里尽量既有平价也有中价，方便按预算改编。
- 场合尽量分散，至少覆盖通勤、约会/周末、婚礼宾客三类，与演示脚本中的“户外婚礼”对得上。

### 4.2 图片

- 只用两种图片：顾问自己拍摄的，或商家书面授权可用于本项目的。从电商页面、社交平台直接保存的图片不能用。
- 只拍商品本身：平铺、衣架悬挂、细节特写。**不使用任何人的身体照片**——包括顾问本人的上身照、模特图、街拍和用户照片。手头唯一的图片里有人，就把图片留空。
- 图片可以留空。无图的单品仍然有效，演示时可用色块和名称展示。
- 现阶段图片只写链接或文件名，图片文件先由顾问保管，不要放进仓库；何时入库、以什么方式入库等授权确认后再定。

### 4.3 购买链接

- 填公开可访问的商品页链接，去掉推广、追踪参数。
- 列出某个店铺的链接只表示“这件可以在这里买到”，不代表与该店铺、品牌有任何合作、代言或佣金约定。导购佣金目前只是方案提案，尚未与任何商家约定。
- 演示前统一复核一次：链接能打开、商品在售、价格与 `price` 一致，并更新 `price_checked_at`。

### 4.4 隐私与内容边界

- 不写任何人的身高、体重、三围等身体数据；`size_note` 只描述商品尺码。
- 不写主理人或任何人的真名、电话、住址、社交账号。
- 不出现明星名字、明星同款等表述，也不暗示任何品牌合作。
- 名称与风格说明写商品和搭配本身，不写对某个人的评价。

## 5. 交给团队

填好后把表格或 JSON 交给项目发起人。转成 JSON 时团队会检查：编号唯一、`item_ids` 都能找到对应单品、类别与 `image_rights` 只用规定值、价格为数字。发现问题会回到这份表格修改，不在转换时自行改动顾问的内容。
