## 1. 产品目标

以人物审美、艺术化衣橱和真实可旋转服饰，连接灵感发现、商品理解与选购。
用户既可以进入空间探索，也可以直接搜索人物、风格、标签、品牌和品类。
站内统一购买与后台整合其他电商供应是重点评估方向；不再把外链作为唯一产品终点。
真实交易须具备合法供给、收款、履约及售后条件，尚未确定商业模式。

“明星衣橱”仍为工作名称，未完成名称可用性核查。
明星参与、品牌合作、原物来源与销售授权没有确认，不能作为既成事实对外表达。

## 2. 本轮已确认的体验方向

以下为方向确认，不是功能完成记录；确认来源对应决策记录 D01–D14。

| 模块 | 已确认要求 | 仍需决定或验证 |
|---|---|---|
| 首页 | 浅弧透视轮播，中央最大正对，两侧部分露出 | 预览制作方式、自动播放与首批数量 |
| 人物信息 | 预览下方头像、姓名、一句风格介绍及进入按钮 | 人物内容、来源和授权 |
| 视觉 | 暗背景、未来感、玻璃卡片、投影与层次光影 | 具体视觉方案与实机效果 |
| 手机 | 响应式，手指切换和点击，进入衣橱前横屏提醒 | 是否强制横屏、竖屏替代行为 |
| 衣橱 | 电影式镜头，选中服饰聚光到中央舞台 | 旋转模式、镜头衔接、返回与控制细节 |
| 详情 | 右侧玻璃信息卡，服饰本身真实立体且可旋转 | 入选服饰、资产、规格映射及性能 |
| 发现 | 完整搜索与导航，覆盖人物、风格、标签、品牌、品类 | 词表、数据量、排序与具体实现 |

技术可行性优先，空间应保护隐私；避免复刻真实私人住宅布局及敏感生活信息。

## 3. 核心旅程与信息架构

建议由首页、衣橱目录、单品目录、统一搜索、衣橱空间及独立详情构成内容层。
交易就绪后再开放可执行的购物袋、结算、订单和售后服务。

| 旅程 | 目标 |
|---|---|
| 首页 → 人物与风格 → 衣橱 → 服饰 | 从探索自然到达准确单品 |
| 姓名或别名 → 结果 → 衣橱或单品 | 识别正确人物，不混淆同名 |
| 品牌、品类、风格 → 筛选 → 详情 | 高效找到符合条件的内容 |
| 分享 → 单品详情 → 来源衣橱 | 不必从首页重新操作 |
| 规格 → 真实可用的购买路径 → 服务 | 价格、来源、责任与状态可信 |

3D 与普通列表应引用同一商品身份；详情、分享与搜索不应依赖场景成功加载。
访客浏览、返回恢复、同组 OR／跨组 AND、减弱动态和列表回退为建议细节。
详见[信息架构与搜索](信息架构与搜索.md)。

## 4. 真实 3D 与素材能力

所有纳入核心选中与旋转体验的服饰，都需要完整真实模型；入选数量仍待收敛。
不能用“一个 GLB 加其余图片”宣称整个核心三维目标已满足。
图片、图文目录与兼容回退可作为补充，但不能冒充真实三维观察。

| 类型 | 可如实提供 | 边界 |
|---|---|---|
| 完整真实模型 | 经检查后的正侧背旋转、缩放 | 不自动证明尺寸、材质、试穿或人物归属 |
| 连续角度照片 | 明示的图片序列观察 | 不是三维几何 |
| 正反面图片组 | 标明的正反切换 | 不能称完整 360° |
| 单张图片 | 放大和局部细节 | 不制造未知背面 |
| 静态概念图与 HTML Slides | 表达布局、流程和设计意图 | 不是应用、模型或交互通过证据 |

核心模型需要对应服饰、变体、来源、代表规格与精度说明。
射灯与氛围不能替代可读商品资料；建议提供中性检视信息辅助判断颜色和细节。
详见[服饰详情与 3D 体验](服饰详情与3D体验.md)。

## 5. 商品事实与购买边界

本人原件、本人推荐、同款新品和相似款分别管理，不从主题空间推断关系。
唯一二手件与普通颜色尺码 SKU 的库存、成色及交易要求不同。
详情按展示或可售状态考虑名称、品牌、材质、规格、护理、成色、关系证据、资产范围、价格时点、卖方、配送、费用及退换规则。
缺失资料应说明或不开放相应操作，不用生成描述代替商品事实。

交易需要比较导购、授权多商家、平台销售或自营路线，尚未选定。
统一前台需要真实披露销售、收款、履约和售后责任，抓取商品页不等于获准销售。
若无真实交易能力，演示不实际收款、不承诺库存、不生成伪装真实成交的订单。
详见[交易与履约方案](交易与履约方案.md)。

## 7. 候选验收与未决问题

以下均待实际执行，不是测试通过结果：

- 首页切换后，人物、风格、预览与进入目标保持一致。
- 搜索与筛选能解释结果，空结果与请求失败有不同出口。
- 分享可直达详情，返回恢复位置，手机横滑与纵滚不冲突。
- 选中、灯光、镜头、真实模型与信息卡对应同一服饰，并可返回。
- 核心服饰能观察真实侧背面；回退明确标明，不计作三维完成。
- 手机方向变化、弱网、模型失败、无 WebGL、键盘和减弱动态有可用路径。
- 商品原件／同款／相似、模型规格与可售状态准确。
- 开启真实交易前，报价、幂等、拒单、退款、客服和对账可执行。

目标用户、市场、首批人物、素材、技术栈、设备、性能阈值与范围仍需确认。
