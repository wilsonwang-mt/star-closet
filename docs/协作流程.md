# 协作流程

面向中文沟通、各自使用 AI agent 的团队。目标是让每个人拿到清楚的小任务，交付后其他人能够继续。

## 接任务前

让 agent 阅读 AGENTS.md 和相关文档，明确：

1. 要交付什么。
2. 可以修改哪些文件。
3. 如何判断完成。
4. 哪些决定或操作不在授权范围内。

当前只做文档与讨论。编码授权须由项目发起用户明确给出，不能把方案讨论自行转成开发批准。

## 小任务交接模板

- **任务名称**
- **背景**：为什么做，相关文档在哪里。
- **目标**：一个可检查的结果。
- **允许修改**：文件或范围。
- **验收**：少量明确检查项。
- **边界**：不能做的操作与未决定事项。
- **依赖**：需要的资料、决定或授权。

简单任务不需要填长表。

## 当前可用的任务示例

**任务名称：澄清服饰展示类型**

背景：需求包含放大、翻面和 360° 查看，首批素材可能同时含有图片与模型。

目标：补充不同素材支持的交互，避免把图片描述为真实 3D。

允许修改：docs/需求说明.md 的素材与交互部分。

验收：区分单张图片、正反面图片组和真实 3D；清楚说明缺失素材与未验证效果。

边界：不写代码，不生成或上传素材，不声称获得明星或品牌授权。

依赖：若需确定具体商品，先取得素材来源与使用权信息。

## 提交与审阅

取得访问权限后，每个小任务使用独立分支，用简洁中文说明改了什么、为什么改、如何检查。

合并前检查：

- 是否遵守任务范围。
- “已确认”“建议”“待验证”是否准确。
- 需求、技术决策和任务是否一致。
- 是否存在无依据的合作、授权、测试或性能表述。
- 是否泄露个人资料、凭据或私人场景信息。
- 链接与文件路径是否有效。

不要为了文档协作添加 CI、依赖或脚本。审阅和合并按实际授权执行，收到任务不等于获得额外权限。

## 有分歧时

对产品取舍、技术路线和素材授权的分歧，先提出选项、影响和待决定问题。需要用户决策的内容保持“建议”或“待验证”。

聊天新决定与文档不同时，记录用户明确决定的范围和日期，再更新文档。不要默默覆盖。

## 交付说明

- 完成内容及文件。
- 实际检查和结果。
- 尚未解决的问题。
- 下一步建议，以及是否需要批准。

当前没有应用程序和测试命令。文档检查不能称为“构建通过”或“功能测试通过”。

## 私有仓库与对外操作

私有仓库也需要检查敏感内容。仓库准备不会自动给团队成员授予访问权限。

邀请协作者、修改可见性或安全设置、发布或部署、上传素材、联系第三方、购买服务等操作，都需要对应的明确授权。创建私有仓库不包含这些后续动作。
