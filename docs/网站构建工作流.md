## 4. 分支、提交与合并规则

1. 每个 agent 在独立 git worktree 中工作，开工前 `git fetch origin && git reset --hard origin/feat/core-adapt-20261015`。
2. 只改本角色列出的路径；中文提交信息，末尾加 Co-Authored-By 行。
3. 代码任务完成前在 `app/` 内运行 `npm run typecheck`、`npm run lint`、`npm run build`，全部通过才推送，如实汇报结果；文档任务做链接、编号与状态一致性检查。
4. 推送前 `git fetch origin && git rebase origin/feat/core-adapt-20261015`，冲突时保留双方内容；再 `git push origin HEAD:feat/core-adapt-20261015`。被拒就重复，最多 3 次。
5. 不推送 `main`，不 force push，不部署。合并到 `main` 由集成角色在用户确认后另行处理。
6. 不读取、不打印、不提交任何 `.env*` 与密钥；验证用本地 PGlite（`npm run db:setup`）与规则模式，不连接用户的 Supabase。
7. 开发测试只用合成图或纯色占位图，任何人的身体照片都不得进入仓库。
