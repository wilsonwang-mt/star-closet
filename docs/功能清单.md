# 功能清单与版本候选

整理批次：2026-10-15。本文是产品范围与验收矩阵，不是已完成功能清单。

当前交付为文档和演示资料，应用尚未实现；任何功能均不能仅因列入表格而标记完成。
相关文档：[PRD](PRD.md)、[需求说明](需求说明.md)、[信息架构与搜索](信息架构与搜索.md)、[实现架构与功能映射](实现架构与功能映射.md)、[技术决策](技术决策.md)、[任务清单](任务清单.md)。

## 1. 状态与优先级

需求状态：

- **已确认要求**：2026-10-14—15 用户对话中明确的产品方向，不等于实现完成。
- **本轮明确规划**：用户要求纳入本轮产品方案的功能维度；匹配规则、布局及上线阶段仍需评审。
- **建议**：为补全完整旅程提出，仍需评审范围与成本。
- **候选后续**：本轮可以完整研究，实施依赖商业或范围决策，不默认进入首版。
- **待决**：存在影响方案的选择，不能预先固定。

计划级别：

- **核心验收**：已确认体验的必要部分，但实施时间与数量待批准。
- **建议 P0**：建议首批验证完整旅程所需，不代表用户已批准开发。
- **建议 P1**：核心旅程之后评估，不阻塞已批准的最小验证。
- **候选阶段**：先确认业务能力再制定完整需求。

所有应用功能当前均未实现。本文不选择技术栈、不承诺首版数量或交易模式。
“已确认”不能从研究报告、静态示意图或团队自行判断推导。

## 10. 建议验证顺序

1. **资料与范围**：确认人物／商品身份、素材可用性、首批覆盖、目标设备与商业模式。
2. **核心体验验证**：在批准范围内验证完整服饰模型、选择、旋转、射灯、详情与返回。
3. **发现闭环验证**：首页或搜索 → 衣橱／列表 → 同一服饰详情 → 真实可用出口。
4. **设备与失败验证**：竖屏、横屏、低端／无 3D、网络失败及内容下线。
5. **商业扩展评审**：如选择站内交易，再完整设计规格、购物袋、支付、订单与服务。

上述是建议顺序，不是编码授权；文档、技术栈批准和正式实施批准分别记录。
