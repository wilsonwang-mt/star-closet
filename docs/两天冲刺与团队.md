## 二、两天内证明什么

v0.3 同时讲清两条路径：创作者“媒体/语音→Agent 草稿→确认→审核建橱”；普通用户“发现→语音挑选→试衣间→本人形象/试穿”。
原有真实 3D 服饰聚光、旋转和玻璃详情体验仍是核心，不因新增 AI 而被图片旋转替代。
硬门槛是完整真实可旋转的三维能力；GLB/glTF 只是本冲刺优先候选格式，文中 GLB 样板不代表用户已指定唯一格式。
正式平台的搜索、交易和运营架构另见[实现架构与功能映射](实现架构与功能映射.md)，不要求两天全部建成。

| 层级 | 候选范围 | 验收证据 |
|---|---|---|
| 硬门槛 | 一件来源可用、完整真实可旋转的服饰模型，GLB/glTF 为候选 | 实际资产、来源与许可、正侧背观察录屏、设备记录 |
| 体验核心 | 一个高完成度艺术化衣橱、聚光舞台、右侧玻璃卡、返回 | 浏览器实操，不能只给渲染截图 |
| 发现入口 | 浅弧卡、头像/姓名/风格介绍、简版统一搜索 | 鼠标/触摸切换，人物/风格/品牌/类别可命中 |
| 手机 | 横屏提醒、触摸旋转、可读信息与恢复 | 真实手机旋转前后选择不丢失 |
| 内容建议 | 一件 3D 主服饰，另 3–6 条有来源目录为候选 | 仅图片内容明确标注，不计入真实 3D 完成数 |
| 交易说明 | 可选演示结账与模拟订单 | 全程标“演示”，不收真实支付或配送资料 |
| Agent 建橱 | 一组许可明确的照片/视频/语音样例，生成草稿、纠正、确认与审核流程 | 实际运行才标实操；状态图/预录概念不能写成已接 ASR/建模 |
| 语音试衣间 | 一句穿搭需求命中服装/配饰，并确认加入独立试衣间 | 可纠正转写、可撤销，不编造真实商品 |
| 本人形象/试穿 | 明确模式的概念流程、真实预录或可验证 2D 样板为候选 | 不冒充精准个人 3D、实时生成或真实合身；主服饰完整 3D 另验 |
| 商业与私密 | 点赞/收藏、私密方案、门票及分成的状态示意 | 不真实收费，不把前端锁遮罩当权益保护 |

一个衣橱、一件真模型、3–6 条目录是工期建议，尚不是用户批准的正式首版数量。
多卡展示若包含未开放空间，明确写“概念预览/尚未开放”；不做暗示已可进入的空入口。
没有明星/品牌许可时采用准确标注的虚构人物或授权内容，不冒充真实衣物、合作与代言。
五类是可重叠发现/准入入口，不能为了 Demo 造五种互斥账号；均有公共审核，普通人申请路径也要画清。
试衣间、持久私密衣橱与结算购物袋分别解释；只展示功能状态不等于已安全保存个人数据。
个人照片默认不训练；演示优先用许可明确/虚构样例，不上传真实用户隐私进公开仓库或 Slides。
不承诺真实收款/供货/分账、多房间、精确人体测量、精准 3D fit、实时布料或完整 CMS 在两天完成。
完整产品仍包括个人形象/试穿；比赛用概念或 2D 只是一种诚实标注的候选呈现，不是删除该产品目标。

## 四、最小实现方式：两条路径共用可信目录

这是方案，不在本轮直接创建对应应用文件。

1. 一套目录表达 owner、可重叠入口/主题、人物/组织、别名、单品/配饰和来源；普通搜索不全改成 LLM。
2. 创作者媒体→结构化草稿→用户纠正/确认→审核，明确处理进度与公开范围；无实际模型调用则只演示流程。
3. 用户语音→可修正文本→有权单品/配饰→确认加入试衣间；不直接加入购物订单或执行付费操作。
4. 当前衣橱加载真实 GLB，聚光旋转与玻璃卡保持独立状态；手机旋转不重置单品或试衣间。
5. 本人同意→形象/试穿按实际能力标 2D/3D/预录/概念，保存版本和限制，不用画面逼真代替 fit 验证。
6. 点赞、收藏、私密衣橱、门票/分成先给状态和规则；演示订单用明确按钮，不调用真实付款/供货。

Agent 媒体、任务/取消、个人隐私、权益校验和账本的正式接口见[实现架构与功能映射](实现架构与功能映射.md)。
试穿能力与来源边界见[AI试穿与个人形象](AI试穿与个人形象.md)；预录必须来自实际结果，纯设计动画写“概念”。

R3F/Three.js 是候选，Spline 是比较项；授权后用同样板在有限时间内选一路，不双线造两套。
不把静态 HTML Deck 当成应用雏形继续扩写站点代码；两种交付的授权和验收保持清楚。

## 六、没有 3D 美术或可用模型怎么办

1. 先核现成、许可明确的服饰 GLB 是否可用，必要时安排短期技术美术清理；不假定素材网站均可商用。
2. 检查正反面、UV、材质、比例、孔洞、穿插和手机表现，下载成功不等于通过。
3. 不在两天临时引入完整摄影测量、布料仿真或从零精细制衣作为唯一出路。
4. 生成式/参考重建资产必须注明性质，不能作为某明星真实衣物或真实背面的事实证据。
5. 周四 15:00 不通过则立即换许可明确成品与必要清理；17:00 仍无合格真模型，真实 3D 目标判未达成。
6. 只有比赛允许概念类时才考虑提交概念方案，并标清缺口；不以图片旋转、视频或渲染图假装满足完整真实可旋转 3D 门槛。
