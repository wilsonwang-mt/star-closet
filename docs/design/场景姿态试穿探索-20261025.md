## 二、三个方案共同遵守

1. **标准图保留，并且排第一**：纯色背景站姿是唯一的合身参考；场景图统一标注「AI 场景示意 · 合身以标准图为准」，不写“尺寸准确 / 保证合身”。
2. **衣服以标准试穿结果为准**：场景图都拿本人已有的标准试穿图做衣服输入（`lib/scene` 已经这样做），换场景、换姿势时衣服不跟着变。
3. **不自动生成**：都是用户点了才生成；Live 仍然按需。
4. **私有**：只用本人的数字分身，结果只给本人看，不进入公共内容（AI 试穿与个人形象 §公共策展独立副本）。
5. **合并而不是另起一套**：三个方案都把 `lib/scene` 扩展成通用的「场景渲染」能力（输入：标准试穿图 + 场景 + 姿势），单品页「上身效果」改用同一套。
6. **缓存**：按 用户 × 单品或整套 × 场景 × 姿势 只保留最新一张（沿用 `lib/scene` 的做法）。

## 三、三个方案

| | A 自选场景与姿势 | B 把封面模特换成我 | C 场合大片 |
| --- | --- | --- | --- |
| 一句话 | 在试穿结果里自己挑场景、挑姿势，生成一张 | 搭配封面就是主理人选好的场景和姿势，一点「看我穿」，把封面里的模特换成自己 | 给一整套按场合拍一组 4 张大片：不同姿势、同一个生活场景 |
| 谁来选 | 用户（场景 × 姿势两组选项） | 主理人（封面已定） | 场合（这套的场合标签决定场景，系统排好 4 个姿势） |
| 放在哪 | 一键试穿与整套试穿的结果面板：标准图下方一条「换个场景」胶片，加两组选项 | 搭配页、首页「按场合整套」和衣橱页搭配卡的封面上：「模特 / 我」切换 | 试衣间每套搭配的卡片里：「生成场合大片」，生成完成后可横滑翻看，可按需生成 Live |
| 一次生成 | 1 张 | 1 张（每套每人一次，缓存） | 4 张（一组） |
| 等待 | 约 30–100 秒 / 张（现有超时 100 秒） | 同左，可在浏览时后台预先生成 | 一组约 1–2 分钟，后台生成、完成提醒 |
| 优点 | 最自由，覆盖「我想看自己坐着 / 在婚礼上」这种具体诉求；和现有场景库直接衔接 | 最直接回应“就像选衣服之前的模特场景图一样”；零选择，模特与自己一键对比，最有“换上身”的惊喜 | 最有仪式感，像一组时装大片，适合分享与决策；和「按场合整套」打通 |
| 缺点与风险 | 选项多，用户要做选择；每张都要等 | 每套只有一个场景、姿势由封面决定；**身份替换最难**——第一次生成保留了原模特的脸和发型（见实测） | 一次 4 张、成本最高；等待更长；场合不准时整组都不合适 |
| 适合 | 想要控制感的用户、单品页与试穿结果 | 浏览中的冲动与惊喜，首页、搭配页 | 试衣间里做最终决定、分享给朋友 |

## 四、示意图实测（Weave · Nano Banana Pro · 1K）

- 标准图：演示人物 f01 + 6 件单品图，一次生成，6 件全部准确（风衣、围巾、T 恤、牛仔裤、乐福鞋、斜挎包）。
- A、C 的 7 张场景图都只用标准图做输入：人物、发型、衣服在坐姿、侧身、倚靠、行走、回眸、半身细节里都保持一致，包括风衣背面的腰带与肩部结构。
- B 第一次（输入标准图 + 封面）：场景、姿势、构图几乎与封面一样，但**人还是封面原模特**（短发、原来的脸）。重试一次：加入演示人物正脸照，并明确只把封面当场景与姿势参考，结果换成了演示人物（长发、本人的脸），场景与姿势仍与封面一致。结论：B 可行，但不能直接把带人的封面交给模型；正式做时先把封面里的人去掉做成「空场景」，或只把姿势写成描述，并加入本人正脸照。
- 本次共生成 10 张（含 B 的一次重试），消耗 Weave 积分 110（每张 11），用户事先批准。
