# Star Closet 视觉规范 · v5「电影感买手店」

**定稿**：2026-10-16，发起用户回复“v5 方向对了，定稿”。参照样稿：[电影感样稿v5.html](电影感样稿v5.html)。可直接引入的变量与组件类：[tokens.css](tokens.css)。

本规范替代此前设计探索中“科技暗色玻璃”的视觉描述；暗场、玻璃信息卡、聚光与电影式镜头的原有需求（VD06–VD08）继续有效，只是表达方式改为本规范。

## 1. 一句话

**界面浮在一个被统一光线照亮的真实空间上。** 画面负责氛围和质感，界面只负责信息和操作，越少越好。

## 2. 画面分层（从后到前）

| 层 | 内容 | 规则 |
| --- | --- | --- |
| 1 场景 | 全屏的电影画面或视频（衣橱、生活场景） | 来自 `keyframes/` 或 Higgsfield 视频；缓慢推镜；进场从虚焦暗场推到清晰 |
| 2 氛围 | 暗角、上下渐隐、射灯光束、光束里的微尘、胶片颗粒 | 只在深色模式加光束和微尘；颗粒深色 .14、浅色 .08 |
| 3 内容 | 刊头、一张玻璃信息卡、列表行 | 每屏最多一张主卡；卡片之外不放装饰 |
| 4 操作 | 一个主按钮，加至多一个圆形次按钮（如打赏） | 主按钮固定在底部安全区内 |

## 3. 模式

- **深色（Night Edit）为默认**，延续早期 v0.3 规划：深石墨底、暖白文字、香槟金实心按钮。
- **浅色（Morning Edit）**：米白、日光、香槟金点缀，主按钮为暖黑实心。
- 跟随系统设置；可在设置里手动切换（`<html data-theme="dark|light">`）。
- 同一屏在两种模式下用对应的场景图（夜间或日间），不能只换界面颜色。

| 角色 | 深色 | 浅色 | 用途 |

| 主文字 | `#F4F2ED` | `#1F1C18` | 标题、正文 |

## 5. 字体

| 用途 | 字体 | 规格 |
| --- | --- | --- |
| 刊头 `STAR CLOSET` | Bodoni Moda | 15px，字距 .42em |
| 英文引题（The Look、Re-styled for you） | Bodoni Moda 斜体 | 11–12px，字距 .12em |
| N° 编号、价格 | Bodoni Moda（编号用斜体） | 编号 36px，总价 32px |
| 中文标题 | 思源宋体 Noto Serif SC 400 | 28px，字距 .12em |
| 风格说明 | 思源宋体 | 12–13px，行高 1.85 |
| 界面文字、按钮 | 思源黑体 Noto Sans SC 300/400 | 正文 14px；按钮 13px，字距 .22em |

杂志元素：刊号式副刊头（`N°01 — Night Edit`）、竖排图注、细线分栏。每屏最多用两种。

## 6. 玻璃（通透轻盈）

- 背景几乎透明：深色 `rgba(255,246,230,.08)`，浅色 `rgba(255,253,248,.28)`；模糊 14px。
- 只保留一道顶部细高光和 0.5px 内描边，外投影很淡。
- 不做厚重反光块、不铺满全屏、不叠两层以上玻璃。
- 被换掉的单品用 1px 香槟细线，加每 7 秒一次的轻扫光。

## 6.1 顶部导航（2026-10-16 用户补充）

- **形态**：悬浮在顶部的玻璃胶囊条，两端半圆（`.sc-nav`），宽度为屏宽减 32px、最大 720px，高 52px，距顶部 12px（加安全区）。
- **质感**：与信息卡同一套玻璃（更强一点的 18px 模糊），顶部细高光，外加两层柔和投影，让它像一张浮在画面上的卡片。
- **内容**：左侧刊头式品牌字 `STAR CLOSET`；右侧 2–4 个链接（衣橱、试衣间、我的档案）和主题切换；当前页用 `aria-current="page"` 高亮。手机上链接多时收进一个圆形菜单按钮。
- **自动收起**：向下滚动超过 8px 时加 `.sc-nav--hidden` 向上滑出；向上滚动、回到页面顶部或键盘焦点进入导航时立即出现。衣橱场景页首次进入时先显示 2 秒再允许收起。开启“减弱动态效果”时不做位移动画，直接显隐。
- **可点区域**：每个链接至少 36px 高，整条至少 44px 可点高度。

## 7. 动效

| 动效 | 时长与曲线 | 用在哪里 |
| --- | --- | --- |
| 场景进场：虚焦暗场推到清晰 | 3s，`cubic-bezier(.22,.61,.2,1)` | 每个场景页首次进入 |
| 场景推镜：缓慢放大 | 22s 往返 | 只用于静态场景图；有视频时停用（视频自带运镜） |
| 卡片浮起 | 1.1s，`cubic-bezier(.2,.7,.2,1)`，依次延迟 0.1–0.3s | 信息卡、列表行、按钮 |
| 衣服落杆、回弹、阻尼摆动 | 落下 1.25s `cubic-bezier(.3,0,.45,1)`，摆动 ±0.9°、6.5s | 去背景单品挂在衣杆上时 |
| 鞋包落地压缩回弹 | 1s | 去背景单品放在展台上时 |
| 金箔流光 | 9s 循环 | N° 编号、总价 |
| 打赏礼物上飘 | 2.6s，7 个依次间隔 120ms | 打赏按钮（演示用，不真实扣款） |

开启“减弱动态效果”时关闭所有循环动画，只保留淡入。

## 7.1 动效品质标准：对标 apple.com 新品页（2026-10-16 用户要求）

用户原话：“千万不要做成一个平庸的产品。要打磨到足够精细，且 interaction 和 animation 要达到 apple.com 每年的新品详情页面的标准。”

**原则**
1. **一切运动都有物理依据**：位移和缩放用弹簧（spring），有质量和阻尼，不用生硬的线性或固定时长；可以被手势打断，并从当前速度接着走。
2. **滚动即叙事**：长页面用“粘性分段 + 滚动驱动”的方式讲故事，标题、画面、数字随滚动进度逐层出现，滚动停下画面就停下。
3. **连续而非跳转**：从首页预览到衣橱内部、从单品到详情，用共享元素过渡（同一张图或同一段视频放大推进），不出现白屏或整页闪切。
4. **克制**：一屏只有一个主角在动，其他元素静止或极轻；没有为了动而动的装饰。
5. **60fps**：只动 `transform`、`opacity`、`filter`；不在动画中改布局属性；大图懒加载，视频只播放可见的那一段。

**落到本产品的关键时刻**
| 时刻 | 做法 |
| --- | --- |
| 首页浅弧轮播 | 拖拽跟手，松手按速度惯性吸附到最近一间；侧卡透视、缩放、模糊随距离连续变化；姓名与按钮保持正面不倾斜 |
| 走进衣橱 | 点击后预览画面放大推进成衣橱内部（共享元素过渡，约 900ms 弹簧），界面文字先淡出、到位后再浮起；返回时反向收回到原卡片 |
| 衣橱内滚动 | 粘性场景 + 滚动驱动：随滚动镜头缓推，单品逐件落到衣杆上（重力回弹），风格说明逐行浮现 |
| 一句话改编 | 等待时光束扫过当前搭配；结果出现时被换掉的单品先淡出、新单品从上方落入，总价数字滚动到新值 |
| 3D 形象 | 模型轻落回弹后缓慢自转，拖拽跟手并带惯性 |
| 导航 | 悬浮胶囊随滚动方向平滑收起或出现（见 6.1） |

**技术建议**：动效库用 Motion（framer-motion，弹簧、手势、布局动画）；滚动驱动优先用 CSS scroll-driven animations，不支持时退回 Motion 的 `useScroll`；页面间过渡用 View Transitions API，不支持时用共享布局动画模拟。

**验收**：在手机（375×812）和桌面（1440×900）各录一遍核心路径；掉帧、闪烁、布局跳动、动画无法打断、文字随透视倾斜，均算不通过。开启“减弱动态效果”时，全部改为淡入淡出。

- AI 生成的场景与人物使用徽章：`AI 生成场景示意 · 合身未验证`。
- 试穿结果按模式标注：`2D 生成预览` / `非本人 3D 模型` / `合身：未验证`。

## 10. 给 app 会话的落地清单

1. 根布局引入 `tokens.css` 与三款 Google 字体；`<html>` 默认 `data-theme="dark"`，提供切换。
2. 场景页用 `.sc-scene` 结构：`__media`（img 或 video，video 加 `muted playsinline loop autoplay` 并给 `poster`）+ `__vignette` + `__fade-top` + `__fade-bottom` + `.sc-grain`；深色加 `.sc-beam`。
3. 信息卡用 `.sc-glass`，列表行用 `.sc-glass.sc-glass--row`，被换掉的行加 `.sc-glass--changed`。
4. 顶部导航用 `.sc-nav`（含 `__brand`、`__links`、`__link`），滚动方向控制 `.sc-nav--hidden`。
5. 主按钮 `.sc-cta`，次按钮 `.sc-cta--ghost`；文字类用 `.sc-masthead`、`.sc-kicker`、`.sc-display`、`.sc-number`、`.sc-meta`、`.sc-foil`。
6. 素材从本目录复制到 `app/public/`，不要改动本目录内的文件。
