本页是设计评审材料。新 v0.3 概念图展示建橱、搭配、试穿与个人空间；另保留 v0.2 早先视觉基线。所有人像、商品、数量和预览都是虚构静态示意，没有执行上传、录音、Agent、试穿或支付。

创作者与团队

把素材交给 Agent，
把发布决定留给人。

照片、视频和语音帮助整理故事与服饰，先形成可编辑草稿，再核对来源、资产和公开范围。

  • Agent 追问缺失信息，不把推测写成事实。
  • 审核后才能发布；图中尚未呈现完整发布结果。
  • 素材整理不等于已经制作真实可旋转 3D。

大众搭配发现

一句话，
找到服装与配饰的组合。

按场景、风格和预算表达诉求，从公共策展中寻找搭配，再把候选组合加入个人试衣间。

  • 语音与文字都是入口，确认条件后再推荐。
  • 说明衣服、鞋包、来源与选择理由。
  • 示例名称和数量不是真实商品或运营数据。

个人试衣间

在本人形象上，
比较喜欢的搭配。

组合保留在个人试衣间，化身未就绪时先创建或导入，再进入一键试穿的目标体验。

图中的人像、多角度和候选款式都是生成示意，尚未建立真实商品与模型的逐项映射；不同领型卡片不构成服饰对应验收。它不能证明精确本人重建、3D、尺码、布料或合身准确性。

个人空间与内容权益

自己的衣橱，
只属于自己。

个人私密衣橱仅本人可见，不提供邀请、团队访问或分享。图下方的独家创作者内容是另一个门票入口。

两入口同页仅是静态示意：个人订阅或容量服务不自动包含门票；购买门票也不会公开个人衣橱。私域数据不向创作者开放，后续布局仍需清楚分区。

公共衣橱的五类发现入口

可以来自一个人，
也可以来自一种主题。

公共策展不等于真实私藏或实体住宅。发布主体、内容来源、主题与访问范围分别表达。

明星

主理人或获授权团队的主题与风格策展。

网红／穿搭博主

创作者把审美、服饰与穿搭故事组织成空间。

品牌主题

围绕系列、活动或品牌表达组织内容。

风格主题

按审美、场景与服饰关系发现搭配灵感。

审核个人

个人策展经审核后进入公共发现范围。

这些入口允许交叉：主理人可以同时是穿搭博主，品牌也可以发布风格主题。个人公开策展不会自动公开其私密衣橱。

两条互相连接的产品流程

一侧把风格组织起来，
一侧把灵感穿到自己身上。

以下为流程概念图。每一步都有真实内容、资产或权限前提，不代表对应功能已实现。

创作者／团队 · Agent 建橱

静态概念流程 · 审核后发布

  1. 照片／视频／语音

    提供素材、故事与使用范围。

  2. Agent 建草稿

    整理信息，追问缺失，不把推测当事实。

  3. 编辑与预览

    核对服饰、来源、主题和空间内容。

  4. 审核内容与边界

    区分公开内容、门票内容与私密材料。

  5. 审核后发布

    通过后进入对应发现与访问范围。

照片和视频可以辅助整理，但不会自动成为完整真实 3D。核心服饰仍需要可核验的三维资产；草稿失败或待补充时保留编辑状态，不自动公开。

大众用户 · 从诉求到本人试穿

静态概念流程 · 个人形象由本人控制

“周末看展，想穿得简洁，
但有一点亮点。”

  1. 语音／文字诉求

    表达场景、风格、预算等已知条件。

  2. 服装与配饰搭配

    看到组合、来源、理由与替代选择。

  3. 个人试衣间

    保留候选组合，比较不同搭配。

  4. 准备本人化身

    未就绪时创建或导入，明确使用范围。

  5. 一键试穿与比较

    在本人形象上查看效果，准确性待验证。

一键试穿是目标体验，不等于当前已具备精确尺码判断、布料仿真或合身保证。本人化身与试衣间仅本人可见，不向创作者开放。

三种访问语义

公开、门票与个人私密，
各有清楚的边界。

付费创作者内容与付费个人衣橱是不同服务，不能共用模糊的“私密”概念。

公共策展

先发现，
理解一种风格。

浏览公开内容，点赞与收藏喜欢的衣橱、服饰或组合。

不包括作者草稿或私人材料。

粉丝门票内容

为指定内容，
获得相应访问权。

公开预览与锁定内容分开，购买前说明内容范围、费用与权益规则。

不会因此获得作者的所有私密资料。

个人私密空间 · 仅本人可见

自己的衣橱，
自己的形象。

付费个人衣橱承载本人服饰、搭配和形象资料，仅本人可见。

不进公共搜索，不提供邀请、团队访问或分享。

点赞收藏不会购买商品、解锁门票或改变私密权限。团队协作仅用于创作者公共建橱。具体定价、期限、续费与退款规则仍需细化；本页没有支付或权限操作。
