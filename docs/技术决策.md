更新日期：2026-10-15（新加坡时间）。版本：v0.3。
**当前没有已批准的应用技术栈，也没有可核验的网站应用实现。**

本文件对齐多类公共衣橱、Agent 建橱、个人试衣间/形象、真实 3D、权益与交易方向，保留历史候选供追溯。

| 站内统一购买与供给整合 | 重点评估，商业模式未定 | 先核实责任、报价、支付、履约与售后 |
| 五类公共衣橱入口 | 最新用户方向，具体准入规则待定 | 明星/网红/品牌主题/风格主题/审核个人可重叠，不能变互斥账户 enum |
| 媒体与 Agent 建橱 | 最新用户方向，未实现 | 上传、转码/ASR、结构化草稿、用户确认、审核发布分步骤 |

| 个人形象与一键试穿 | 最新用户目标，能力待验证 | 本人同意、2D/3D 模式、资产适配与 fit 边界分别验收 |
| 点赞收藏、私密方案、门票与创作者分成 | 最新用户方向，规则/费用待定 | 权益、隐私、数字订单、归因和分账独立建模 |
| 应用开发和应用部署 | 未授权实施 | 不初始化工程、安装应用依赖或开启应用服务；静态材料例外继续适用 |

## 2. 路线候选

| 路线 | 适用条件 | 待验证 | 当前状态 |
|---|---|---|---|
| React + React Three Fiber + Three.js | 团队以代码控制镜头、状态与网页整合 | 模型、灯光、转场、手机、性能及维护成本 | 建议评估，未批准 |
| Spline + 网页层 | 团队熟悉可视化场景制作 | 当前账号导出、托管、事件、费用与外部 UI 衔接 | 建议评估，未批准 |
| 其他 Web3D 引擎或框架 | 同样板比较后有明确收益 | 团队能力、资源格式、设备与成本 | 可比较，未选择 |

代码主导时可优先评估 R3F，不能把建议写成已经选型。
Spline 的价格和权益需重新核实，不能假定免费自托管或任意导出保留完整交互。
不因演示材料采用 HTML，就默认应用必须用某个框架或不需要服务端。

AI 路线按能力拆分，不能用“已接一个大模型”代替全部能力验证：

| 能力 | 候选方式 | 选型前必核 |
|---|---|---|
| 音频/视频转写 | 独立 ASR 适配器与可修正文稿 | 语言、口音、噪声、时间、用途及删除条款 |
| 建橱/搭配 Agent | 结构化抽取、受权检索、工具动作提案 | 事实来源、低置信纠正、权限、版本、取消与成本 |
| 个人形象 | 托管或自管重建/化身管线 | 本人授权、输入、身份相似、几何/绑定与生成时延 |
| 试穿 | 2D 生成或已验证 3D 管线分别比较 | 输出模式、服饰适配、遮挡、稳定性和 fit 局限 |
| 推理运行 | 异步任务队列与服务商/自管执行适配 | GPU/模型成本、地域、默认不训练、保留/删除、配额和故障 |

本轮不选商业服务商、不声明具体费率，不在云端或 Mac 安装推理环境，不处理真实用户照片。

## 3. 获授权后的验证顺序

建议先用一个有限样板比较技术和设备，再扩展内容与交易。

1. 核实一件许可清楚、完整正侧背与材质的真实服饰模型。
2. 在艺术化房间验证进入、选中、聚光、旋转、玻璃卡与返回。
3. 记录手机和桌面设备、浏览器、网络、质量档及实际结果。
4. 验证普通目录、搜索、独立详情、分享和返回恢复。
5. 验证弱网、模型失败、无 WebGL、横竖屏及无障碍路径。
6. 再决定扩充核心服饰数量和资产流程。
7. 分别验证媒体→可修正建橱草稿→确认→审核，不用生成结果自动公开。
8. 验证语音查询→已授权单品/配饰→试衣间加入/撤销，避免虚构或越权内容。
9. 本人同意后按独立模式验证个人形象/试穿；2D、预录、概念与真实 3D 各自标明。
10. 验证多租户、付费正文、签名资源、AI 召回与删除链路，再试数字订单/权益/分账。

一个模型只用于首个技术样板，不代表其余核心服饰可用图片替代后算完成。
原一个房间、三个镜头、6–8 件和至少一个 GLB 为历史候选，不是本轮批准范围。
目前没有执行上述代码实验；执行须先取得应用编码授权。

## 4. 系统与数据责任建议

| 范围 | 建议责任 | 不能混淆 |
|---|---|---|
| 浏览器 | 导航、搜索输入、空间、选择、详情与恢复 | 前端成功提示不等于真实付款成功 |
| 目录与检索 | 人物、衣橱、词表、发布态与商品身份 | 展示内容不等于有可售库存 |
| 资产 | 来源、权利、版本、模型与变体映射 | 模型存在不等于精度或授权通过 |
| 报价与交易 | 服务端核实费用、库存、订单、归属和支付结果 | 前端价格不是最终可信金额 |
| 供应适配 | 外部商品、接单、履约、售后状态与补偿 | 网页抓取不是供货或代收款授权 |
| 运营 | 发布、撤回、异常、客服、退款和对账 | 手工流程不能描述成已自动接入 |
| 主体与权限 | 个人/组织 owner、团队角色、对象权利和审核 | 五类发现入口不是互斥账号，审核也不只针对个人 |
| 媒体/AI | 私有上传、转码、作业、版本、草稿和用户确认 | 任务成功不是公开发布，也不是生成精准 3D |
| 个人资产 | 试衣间、持久私密衣橱、化身及试穿结果 | 与购物车分开；付费/到期不扩张素材使用目的 |
| 数字权益 | 门票、私密方案、数字订单和 Entitlement | 搜索可发现不等于全文/模型可免费访问 |
| 归因分账 | 合同/来源快照、应付、冲回、实际结算 | 数据库分账记录不等于资金已经分发 |

人物／衣橱、商品／变体／唯一件、资产、报价、订单、支付、包裹及退款应分别表达。
搜索、空间与详情引用一致身份；历史订单保留当时商品、价格和政策快照。
搜索仅索引已发布且允许展示内容，别名和标签来源可追溯。
仅公共非敏感目录状态可写分享 URL；语音原文、私密/身体条件、个人衣橱与付费上下文走本人鉴权会话，不进入分享链接、日志或公共缓存。
本人私密和团队检索与公共检索分域；无权内容不进入 AI 上下文、摘要、建议词、数量或引用。
owner、身份认证、衣橱主题、可见性、审核态分开；品牌×风格×创作者联名按同一资源 ID 去重。
私密个人原件不因申请入驻自动公开，用户选择待审发布副本；所有公共类型均须审核。
未核实币种与价格口径前，不做跨币种价格排序或虚假实时库存过滤。

## 5. 3D、性能与兼容建议

- 首页预览与真实场景分层加载，具体海报或实时预览方案仍需确认。
- 核心模型逐项检查尺度、UV、材质、背面、透明边缘与变体表示范围。
- 房间镜头与服饰旋转分清控制；降低动态时保留操作与观察能力。
- 聚光和玻璃要兼顾材质细节、文字可读、手机资源与发热。
- 资源有版本、来源和校验，可撤回，不以关闭 TLS 或校验换取可用。
- 性能记录设备、系统、浏览器、网络、缓存、画质与资产版本。
- 架构文档中的体积、时间与帧率是待验证预算，不是实测达标结果。
- 列表、图片和文字是兼容路径，真实三维目标单独验收。

用户参考 miniroom.5title.com 的体验尚未在本云端完整核验，不宣称达到或超过。
本轮静态视觉是重新生成的概念材料，不含真实可交互服饰 3D 模型或真实应用截图。

## 6. 交易技术前置

站内结算必须先决定市场、币种、销售收款主体、供给与售后责任。
支付方案依据正式服务商能力确定，不默认支持预授权、分账或延迟扣款。
下单、支付、供应请求与退款需幂等，回调验签、去重并能处理乱序和丢失。
付款成功但拒单、超时未知、部分供货和退款失败均需补偿及人工路径。
访客查单需验证归属，不只凭可猜订单号；订单、地址与令牌不能进入公开缓存。
真实交易与演示隔离，模拟订单和测试支付明确标识。
实体商品和数字门票/方案分别维护订单、支付归属、退款、账目和政策快照，不能套用同一个履约状态。
数字权益在服务端验款后发放，到期/退款/下架与签名资源、检索/AI 权限一致收敛。
入驻费或免入驻后分成以版本化合同表达；不预设免佣、费率、结算周期或支付商分账能力。
归因规则及来源快照固定于交易时，退款用冲回分录，不覆盖历史收益；真实资金结算单独验证。
详见[交易与履约方案](交易与履约方案.md)，这些能力尚未实现。

## 8. 异步 AI 与个人数据的技术原则

- 上传、隔离校验、转码、ASR、抽取、草稿确认、审核与发布分开，可追踪输入/输出版本。
- AIJob 幂等键绑定身份、任务、输入/同意版本与配置；新输入开新版本，不能污染旧确认。
- 取消是最佳努力；停止后续处理，不展示/发布迟到结果，已产生计算成本不承诺退还。
- 重试有错误分类、次数/费用限额和外部结果查询，不能无限消耗 GPU；进度、等待、失败与费用分别表达。
- 个人照片/视频和派生形象默认私有、不用于训练；真实服务前核外部合同，不凭未验证政策作保证。
- 撤回/删除跟踪原件、代理、形象、试穿、索引、缓存和外部回执；必要最少财务记录单独处理。
- 个人形象不自动等于准确身体测量；视觉相似不等于身份核验，试穿图不保证真实合身。
- 身份/团队 RBAC 与对象/权益校验结合，私密/付费资源从后端到 CDN 和 AI 工具逐层授权。
- 已下载资源不能保证召回；签名链接、缓存失效和限流不能包装为绝对防复制。
