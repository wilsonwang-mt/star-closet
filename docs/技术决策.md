# 技术决策

更新日期：2026-10-12

本文件区分已确认方向、建议与待验证问题。**当前没有已批准的技术栈。**

## 已确认方向

- **镜头组织**：采用电影式、经过编排的镜头体验，优先考虑镜头控制、转场稳定性和单件查看的实现成本。
- **验证顺序**：技术可行性优先，先验证小范围体验，再讨论内容规模。
- **开发边界**：用户要求暂不编码。技术验证目前只可规划，执行代码实验也需要明确授权。

## 路线候选

### React Three Fiber

状态：建议，未批准。

如果团队希望以代码为主控制镜头、交互和后续扩展，可将 React Three Fiber 作为优先评估对象。

待验证：

- 镜头控制与转场是否满足预期。
- 图片、图片组与 GLB 能否采用清晰一致的展示逻辑。
- 模型、贴图及交互在目标设备上的开销。
- 团队维护成本与素材处理流程。

drei CameraControls 文档可作为参考入口，尚未据此完成原型或性能测试。

### Spline

状态：建议，未批准。

如果团队熟悉 Spline，可评估其场景制作与交互流程。是否采用取决于实际功能、导出、嵌入、托管限制和费用。

待验证：

- 当前账号的导出与托管权益。
- 镜头、服饰查看及零售商外链的可实现程度。
- 素材更新、协作与迁移成本。
- 目标设备表现。

价格与方案限制可能变化，选择前应重新核实官网。不能假定某个导出格式保留全部事件和动画，也不能假定自托管能力已包含在账号方案中。

## 候选验证场景

状态：建议，未批准。

用一个房间、三个镜头状态、六至八件服饰与一个真实 GLB 验证完整浏览路径；其余图片素材如实标注。若资产条件不足，可讨论更小范围。

需要回答：

1. 镜头能否稳定进入细节并返回？
2. 真实 3D 服饰是否清晰，操作是否自然？
3. 图片素材能否协调呈现，同时避免误导？
4. 目标设备是否达到约定可用标准？
5. 团队能否以可接受的成本继续补充素材？

这是验证计划，不代表已选择框架、建立工程或完成实验。
