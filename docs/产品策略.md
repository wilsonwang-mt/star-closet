## 1. 产品定位与价值闭环

**让创作者把风格变成可探索的衣橱，让每个人把发现的单品带进自己的试衣间。**

供给端通过照片、视频和语音向平台 Agent 提交内容，生成可审核、可编辑的衣橱草稿。
需求端通过文字和语音寻找服装与配饰，探索公共衣橱、整理搭配，并评估个人形象与虚拟试穿。
平台连接风格内容、可信商品和个人选购，同时管理发布、访问、支付、归因与履约责任。

建议用四个闭环判断平台是否成立：

1. 生产：素材采集 → Agent 草稿 → 人工确认 → 审核发布 → 更新与撤回。
2. 发现：文字／语音 → 人物、风格与单品 → 点赞收藏 → 返回或分享。
3. 个人决策：选品 → 试衣间 → 对比搭配 → 经授权的形象与试穿 → 可用购买路径。
4. 经营：明确付费对象 → 权益或商品交付 → 退款与撤回 → 对账 → 合作方结算。

公共内容、用户照片和货币交易有不同信任要求，不能共用一个“上传成功即上线”的流程。

## 3. 五类公共衣橱的供给与责任

| 类型 | 核心内容 | 入驻与权利核实 | 价值与主要风险 |
|---|---|---|---|
| 明星衣橱 | 经授权的人物风格、穿搭及独家策展 | 本人或合法代理；肖像、原物和内容分别核实 | 强人物兴趣，授权及内容维护成本高 |
| 网红／穿搭博主 | 穿搭组合、推荐及商品讲解 | 创作者、团队及商品关系可核验 | 持续内容与分成动机，避免虚假推荐 |
| 品牌主题 | 秀场、系列、联名或品牌故事 | 品牌或授权方及主题素材 | 专业供给和商业预算，广告须披露 |
| 风格主题 | 风格、场合、年代等编辑策展 | 编辑与素材权利，说明非人物原物 | 冷启动可控，需形成可检索词表 |
| 审核通过个人 | 本人愿意公开的穿搭或衣物 | 本人提交、公开同意和内容审核 | 社区供给潜力，审核、侵权与隐私负担 |

品牌主题中的秀场图、音乐、模特肖像与衣服模型可能属于不同权利方。
风格主题不需要虚构明星背书；个人衣橱审核通过也不等于获得商家销售资格。
公开衣橱应标明人物授权策展、品牌项目、编辑主题或个人分享，不混同真实私人住宅。
个人私密衣橱仅本人查看；审核通过个人的公共衣橱须独立提交和确认素材，不共享私密空间的访问权。

## 4. 多边用户及冷启动

| 参与方 | 要完成的任务 | 平台需要提供 | 为什么可能留下 |
|---|---|---|---|
| 大众消费者 | 找到、保存、搭配、评估及购买 | 高质量检索、试衣间、可信商品与服务 | 历史选品和搭配确实节省决策成本 |
| 创作者及团队 | 低成本持续生产衣橱和内容 | 采集指引、Agent 草稿、协作、审核与经营工具 | 可管理的生产负担和透明收益 |
| 品牌／商家 | 展示商品并获得可核实交易 | 授权接入、商品同步、活动与成交报告 | 可解释的获客与履约成本 |
| 制作与服务伙伴 | 按规范交付素材、模型或履约 | 标准、验收、版本和权限 | 可重复交付及明确结算 |
| 平台运营 | 维持可信供给、质量和财务闭环 | 审核、异常、客服、归因与对账 | 每单与每个衣橱的服务成本可控 |

建议先选一个明确风格或场合，集中消费者、创作者和一家有条件供应方。
五类是平台分类，不必第一天为每类凑数量，更不能用虚构人物充当已入驻供给。
对精选创作者可限额补贴建橱；品牌付费制作与免费入驻分成使用不同合同和成本边界。
先人工辅助跑通生产、反馈和收益，再扩大开放范围；人工服务不能包装成全自动。
在供给质量和重复使用未验证前，不用高额买量同时补齐所有市场两侧。

## 6. Agent 建橱的可行性与资源

照片能提供可见外观，视频能提供连续角度，语音能补充意图和已知资料。
它们不能自动证明品牌、成分、尺寸、背面、货权或授权，Agent 的推测不能直接发布。
建议 Agent 先做转录、素材归组、商品候选、缺项追问、镜头与陈列草稿及文案整理。
商品事实、人物关系、销售资格、付费内容承诺和发布范围由有权限的人确认。
复杂遮挡、反光、透明、褶皱及背面缺失可能需要补拍或专业模型制作。

| 能力层 | 资源需求 | 推荐验证 |
|---|---|---|
| 内容草稿 | 多模态服务、转录、结构化提取、编辑与审核 | 缺项识别、事实误提取率、编辑工时 |
| 空间建橱 | 模板、布局、镜头、碰撞与场景编辑 | 可进入、可选中、无明显遮挡及可返回 |
| 商品真模型 | 采集规范、建模师、材质和资产质检 | 正侧背、尺度、版本和变体映射 |
| 供给接入 | 商家授权数据、报价、库存和责任 | 展示对象与可售 SKU 不串位 |
| 持续服务 | 更新、下架、费用、客服与伙伴管理 | 单衣橱维护成本和交付时效 |

建议以“草稿 → 待补资料 → 待确认 → 待质检 → 可发布”控制自动化边界。
团队协作仅用于公共创作者工作台，设所有者、编辑、审核与结算权限；不向团队开放个人私密衣橱。
优先购买明确的交付结果而非模糊的自动化承诺；本轮不采购或联系服务商。

## 7. 试衣间、个人形象与试穿

F11 不只是购物袋换名字，应帮助跨衣橱保留规格、组合、对比和来源。
试衣间内容分清可售商品、仅展示内容、缺货项和用户自有衣物。
收藏、试穿和加入试衣间不锁库存；最终金额及可售状态在交易时核实。
先验证搭配保存与对比是否有重复价值，再扩展复杂形象生成。

F12 涉及两类独立问题：

- 视觉形象：生成看起来像用户、可用于风格观察的表示。
- 尺寸与服装拟合：身体尺寸、版型、布料、姿态、遮挡和设备一致性。

外貌相似不等于尺寸准确，商品能旋转不等于可以正确穿到任何化身。
照片生成的平面试穿图不计为真实 3D 化身；示意动画不计为物理服装拟合。
建议按非实时预生成、受控姿态、小范围品类验证时延、成本和人工修复率。
失败时保留普通搭配与商品资料，不制造似乎准确的身体或背面。

本人照片、视频和形象需要私密处理、用途同意、删除和撤回路径。
不默认用于公开衣橱、合作方培训、广告或通用模型训练。
未成年人、他人肖像、冒用与敏感图像处理需在开放前确定规则和处理责任。

## 8. 点赞收藏、个人私密与粉丝付费内容

F13 的点赞和收藏是发现与保留信号，不自动证明授权、质量或可分成成交。
达到尚未定义的阈值后，可选择付费创建个人私密衣橱；不自动扣款或强制公开。
阈值究竟按数量、容量、活跃或其他资格计算，以及免费保留范围，均需决定。
不应靠模糊“超过阈值”锁走已保存内容；收费前说明权益、迁移、导出和到期处理。

两种私密必须分开：

| 产品 | 可见范围 | 付费对象与边界 |
|---|---|---|
| 个人私密衣橱 F13／F14 | 仅本人查看，不支持邀请他人访问 | 付费空间、容量或工具，不售卖他人内容权利 |
| 粉丝解锁内容 F14 | 购买者在指定范围和期限内访问授权策展内容 | 取得内容访问权益，不取得真实住宅或人物生活信息 |

“私密”是访问范围和用途约束，不等于真实地址、住宅地图、定位或未经同意的生活细节。
付费也不授予下载原图、再分发、训练或转售权，具体许可在购买前说明。
截图和复制无法绝对禁止，不能把访问控制宣传为绝对防泄露。
撤下、到期、退款、申诉及创作者退出均需有明确规则。

## 9. 商业结构、优先级与赚钱条件

四类业务分别核算：B2B 入驻服务、C2B 数字门票、C端私密衣橱服务（一次/周期待定）、商品成交归因分成。
平台和创作者的商品收益来自同一明确佣金池，不把两方总额重复计为平台收入。
GMV、代收款、创作者应付、平台收入、贡献利润和现金余额分别统计。

| 候选优先级 | 推荐实验 | 为什么 | 放大条件 |
|---|---|---|---|
| P0 基础 | 可信目录、Agent 辅助建橱、试衣间基础能力 | 同时服务供给与消费，不依赖未验证精确试穿 | 发布质量、选品任务和运营成本成立 |
| P1 早期经营 | 有验收范围的品牌／专业创作者建橱服务；有限供给交易 | 服务交付较易核实，能检验供给与订单 | 客户愿付费，单项目或净订单贡献可解释 |
| P2 粉丝内容 | 有权利、稳定更新的数字门票试点 | 需要真实人物吸引力和售后承诺 | 访问交付、续作、退款及结算可执行 |
| P2 个人私密服务 | 仅本人使用的私密保存和明确容量权益 | 一次解锁或周期收费待定 | 付费意愿、留存和服务成本成立 |
| P3 高成本差异化 | 个人 3D 化身和更精准试穿 | 对素材、研发、算力和误差处理要求高 | 品类、质量、成本与隐私验证成立 |

优先级是建议，不否定已确认方向；最终首版和商业试点由用户决定。
不同时用入驻费、平台佣金、创作者佣金和广告收入重复包装同一笔交易。
价格、费率、免费额度、优惠、阈值与归因窗口全部待定。
详见[商业模式与平台运营](商业模式与平台运营.md)及[交易与履约](交易与履约方案.md)。

## 10. 市场证据与验证计划

已有参考包括 Kardashian Kloset 的人物商品、ShopMy 的创作者导购、Indyx 的数字衣橱与 Emperia 的主题空间。
它们只证明相邻模式存在，不证明本项目已形成网络效应、虚拟试穿精度或营收。
本轮没有新增规模、增长率、市场份额或付费转化的实测数据。
开放创作者与大众试衣间拓宽使用场景，同时增加审核、隐私、模型和交易成本。

建议验证：

- 一名创作者从采集到发布需要多少人工、重拍与模型修复。
- 用户能否从自然语言找到准确候选并保留到试衣间。
- 试衣间是否产生重复搭配和回访，而不只是一眼新奇。
- 哪种内容、空间或商品服务真正有人愿意付费。
- 退款后平台净收入能否覆盖制作、算力、客服和获客。
- 是否能在开放个人内容时保持侵权、作弊与私密泄露可控。

## 11. 分阶段与当前边界

当前完成的是规划与静态材料，既有静态线上预览不代表应用具备 F10–F15。
建议阶段为：供给与责任收敛 → 人工辅助样板 → 获授权的有限体验 → 独立商业试点 → 有证据再扩展。
首个样板可以只有有限真模型，但所有纳入核心旋转体验的服饰均需完整真实模型。
一个 GLB 加图片不能代表整体三维目标达标，照片也不自动生成精准化身。
比赛或展示范围需另定，不把五类开放平台和实时试穿全部承诺为两天工程。

下一决策建议：确认首批供给类型与客群、最小试衣间、试穿验真目标和优先账本。
之后明确首版、人员、素材、预算和应用编码授权，再进入工程实施。
