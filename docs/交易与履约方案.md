# 交易与履约方案

更新日期：2026-10-15（新加坡时间）
状态：完整评估草案；商业模式、首版范围与实现方案尚待确认。

最新重点是评估站内统一购买，并在后台整合其他电商供应，使体验连贯。
本文件提出能力、责任与验收，不表示已经接入供应商、取得销售授权或具备支付能力。
商家、经营市场、币种、支付服务商、供应商与履约方式均未确定。
静态材料已获整理授权；应用编码、真实收款、部署、采购与第三方接洽未获相应授权。

## 1. 目标与决定顺序

用户应从衣橱发现服饰后，清楚地选规格、购买、查物流并获得售后。
连贯体验覆盖整个生命周期，而不止是把付款按钮保留在页面内。
需要依次明确体验目标、商业责任、供给、资金流程，再选择技术实现。
合同卖方、收款主体、履约方、退货接收方和客服责任可能不同，必须真实披露。
统一界面不自动赋予平台转售、代下单、代收款或处理商家退款的权利。
能抓取商品页、显示公开价格或生成链接，不等于有货源或销售授权。

## 2. 候选商业路线

| 路线 | 成交与履约 | 付款位置 | 必备条件 | 当前判断 |
|---|---|---|---|---|
| 外链导购 | 零售商成交并履约 | 零售商网站 | 合法展示、可核实链接；佣金另需授权 | 对照或供应不足时的透明方案，不满足完整站内购买目标 |
| 授权多商家平台 | 按合同划分商家与平台责任 | 可在本站，取决于接入 | 商家合同、报价、订单、售后及适配支付 | 重点评估，未选定 |
| 平台统一销售、合作供货或代发 | 平台承担相应销售责任，合作方供货或发货 | 本站 | 合法供货与收款条件、履约和售后能力 | 后续候选，不因界面统一而默认采用 |
| 平台自营库存 | 平台采购、销售并组织履约 | 本站 | 资金、库存、仓配、税费及售后体系 | 不建议作为未经验证的起点 |

统一站内结算是一种体验形态，不等同某一种商业模式。
能否一次扣款、分账和结算，要按实际市场、合同与支付服务商能力核实。
合作方代发不意味着平台没有责任；技术命名不能代替商业决定。
外链路线仅用于比较，不能视为用户已同意放弃站内购买方向。

## 3. 推荐首个真实交易验证

以下为建议，不是已批准首版；每项须在实施前确认。

| 决策 | 推荐验证范围 | 依据 | 待落实 |
|---|---|---|---|
| 市场 | 一个市场、有限配送地区 | 降低税费与配送组合 | 经营与收货地区 |
| 币种 | 一种结算币种 | 避免首轮跨币种报价与退款 | 币种及支付支持 |
| 供应 | 一家正式授权供应商 | 先证明端到端交易成立 | 合同、能力、责任人 |
| 商品 | 少量授权普通 SKU | 降低唯一件竞争复杂度 | 商品、规格、来源与政策 |
| 身份 | 匿名浏览，优先评估访客结算 | 减少不必要注册 | 支付、风险与履约要求 |
| 支付 | 一种正式支持的方式 | 先验证成功、失败与退款 | 服务商、账户与资金流 |
| 履约 | 一种可追踪配送流程 | 减少物流状态映射 | 追踪、异常与退货路径 |
| 客服 | 一个入口、明确人工负责人 | 异常必须有人能处理 | 时段、权限与升级 |

真实验证须覆盖付款、接单、发货、售后与对账，成功扣款不等于完成。
支付沙盒只证明对应测试流程，不证明真实商品已经供货或成交。
如首批必须销售唯一二手件，应先补齐第 6 节要求，再调整范围。

## 4. 阶段与退出条件

| 阶段 | 交付 | 退出条件 | 未满足时 |
|---|---|---|---|
| A：可行性核实 | 市场、责任、供给、资金流与售后表 | 关键条件有可检查依据及负责人 | 保持规划，不真实收款 |
| B：体验演示 | 商品、规格、选品清单和明确标识的结算演示 | 用户理解价格、卖方、配送及演示状态 | 修改流程，不伪装真实购买 |
| C：单供应商验证 | 真实订单、履约、退款与对账 | 成功及失败场景闭环，运营能处理异常 | 暂停扩张，先解决问题 |
| D：多供应商 | 混合购物袋、拆单、部分履约与退款 | 拆单、结算和客服可执行并通过验证 | 保持单供应商范围 |
| E：规模或自营 | 根据需求、成本和资金决定扩展 | 商业与运营能力可承担 | 维持范围或调整模式 |

阶段 B 是验证方法，不代表用户已选择以演示代替长期产品。
实施阶段、真实试运行、采购、签约和发布需要各自对应授权。
文档批准不自动允许应用编码，比赛时间也不解除交易前置条件。

## 5. 匿名选品、结算身份与账户最小化

建议默认允许匿名浏览、查看规格和整理选品清单。
不要求先注册才能了解商品，不默认捆绑手机号验证或营销订阅。
匿名清单说明保存位置、期限与跨设备限制；本机保存不等于账号同步。
结算优先评估访客方式，只收集成交、通知、支付及履约确实需要的信息。
邮箱可作为通知及访客访问的候选方式，具体按实际经营条件确定。
电话、账单地址和身份核验仅在真实要求成立时加入，并说明用途。
必须登录或核验时，提前解释原因，避免到付款前才突然阻断。
购买后可选择创建或绑定账号，不把注册作为查单和售后的附加门槛。
营销订阅独立选择；接收订单通知不自动代表同意营销。

访客订单访问需要真实访问控制，不能只凭可猜测订单号查看。
可评估限时安全链接或联系方式验证，技术选型时确定具体方法。
通知中不暴露完整地址、支付资料或可长期公开使用的访问凭据。
绑定账号需验证订单归属，不能输入同一邮箱就自动展示历史订单。
账号只保留订单访问及安全必需能力，社区、积分、社交资料不自动入范围。

## 6. 普通 SKU、唯一二手件与商品关系

| 类型 | 商品事实与库存 | 交易与展示要求 |
|---|---|---|
| 普通新品 SKU | 颜色、尺码、数量对应真实规格 | 重新核实库存、报价及规格，处理超卖 |
| 唯一二手件 | 一件实物、独立身份与所有权或寄售依据 | 单件竞争控制、限期占用、释放，披露成色与缺陷 |
| 人物原物 | 有可核实人物关系与销售授权 | 不从场景陈列推断本人持有或委托销售 |
| 同款或相似款 | 与场景原物不同的商品 | 独立真实 SKU，明确同款或相似，不静默替换 |

加入购物袋通常不代表预留；确有占用时显示期限和到期结果。
普通库存也可能不准确，预留只能降低风险，不能保证消除超卖。
唯一件不支持可靠预留时，先决定可接受的竞争、确认与退款规则。
不自动以相似款替换缺货；替换须用户明确选择并重新确认金额。
二手与特殊商品的退货限制按真实条件核实，不一概写成售出不退。

## 7. 商品、授权与最终报价

区分商品、SKU、供应商、展示资产与交易报价。
记录商品及供应商 ID、规格、币种、价格、库存状态、同步时间与可售地区。
记录卖方、履约方、配送、售后、来源、人物关系和素材授权依据。
图片、图片组、图片序列与真实 3D 分别标注；旋转效果不等于事实已核实。
本人原物、本人推荐、同款新品与相似风格分别记录。

付款前按规格、数量、地址和配送方式重新计算最终报价。
报价包含商品、运费、可确定税费、优惠、完整应付金额及有效期。
参考价、上次同步价与最终报价分开，不把旧数据当实时保证。
规格、地址、价格变化或报价过期时重新确认，不静默扣取新金额。
保存用户确认的商品、价格、政策与责任方快照，后续更新不覆盖历史。
无法确定完整金额或可售地区时，不开启实际付款。
供给数据来自获授权方式，网页抓取不构成稳定供货合同或库存承诺。

## 8. 购物袋、确认页与费用

购物袋保留商品、规格、数量、供应方和当前可售状态。
结算前复核库存、规格、价格、配送范围、运费、税费及政策变化。
变价或缺货时显示具体变化，不静默删项、改价或替换。
不可购买的收藏项与可结算商品明确区分，避免误以为均可一次付款。

确认页至少显示：

- 商品、规格、数量及对应卖方。
- 每个履约部分的运费、预计时效和配送方式。
- 总额、币种、税费与优惠规则。
- 是否拆单、分批发货或由不同主体履约。
- 各商品的退换货条件与统一求助入口。
- 实际收款方式，以及一笔还是多笔付款。

无法确认全部商品时，先展示可购与不可购部分及处理选择。
不把用户同意购买组合解释为同意任意部分成交。
免邮门槛说明按供应商还是整单计算，取消后的费用变化也需有规则。
结算有普通页面入口，不依赖 3D 成功加载、悬停或高性能设备。

## 9. 多供应商母子订单

区分订单组、供应商子订单、商品行、包裹、售后单和支付记录。
统一订单组不代表一次成交、一个包裹或同一退货地址。
同一子订单可能多次发货，不同商品也可能适用不同取消和退货条件。
必须明确组合是否要求全部成功、部分拒单时是否继续、何时重新确认。
已支付但未被接受的部分，要有可执行退款与状态说明。
候选默认是在付款前尽量完成报价与可售检查，再按用户确认规则执行。
部分失败时展示成功、失败、应退金额和下一动作，不默认整单成功。
若要求全单成功，须有真实预留与补偿能力，不能作无法执行的保证。

## 10. 支付、幂等与补偿

支付方案按实际服务商、市场与模式确定。
预授权、延迟扣款、部分扣款、分账、部分退款均需核实，不默认可用。
付款与供应商接单的先后顺序需结合资金风险及供应能力明确设计。

- 下单与支付尝试有稳定标识，重试使用适当幂等机制。
- 重复点击、刷新、重试不重复扣款或建立重复订单。
- 后台核实结果，浏览器返回成功不是唯一成交依据。
- 验证回调真实性，处理重复、乱序、延迟和缺失。
- 同一事件重复到达不重复累计金额，超时先查询原尝试。
- 支付、订单、供应请求相互关联，可核查最终结果。
- 退款独立标识、幂等并确认结果，发起不等于到账。

| 异常 | 用户状态 | 后台处理 | 不允许的结果 |
|---|---|---|---|
| 付款结果未知 | 正在确认，可查询原订单 | 查询支付方、补收回调或人工核查 | 诱导重复付款 |
| 付款失败未扣款 | 失败，可安全重试 | 确认失败并释放有效占用 | 显示已购买 |
| 已付但拒单 | 受影响商品失败，处理或退款明确 | 补偿并追踪退款完成 | 无订单也无退款 |
| 接单响应丢失 | 确认中 | 按关联号查既有结果后重试 | 盲目重复下单 |
| 部分供应失败 | 成功失败分开 | 按用户确认规则继续、取消或退款 | 全单成功假象 |
| 退款回调延迟 | 退款处理中 | 核实退款记录和支付方结果 | 重复退或谎称到账 |

异常进入可追踪队列，有负责人和下一动作，不以无限重试代替处理。

## 11. 状态与时间线

订单、支付、履约、售后和退款分别记录，再组合为用户可理解状态。
以下状态为候选，待实际接口明确后收敛，不是已实现数据模型。

| 维度 | 候选状态 | 原则 |
|---|---|---|
| 订单 | 待确认、接受、部分接受、取消、完成 | 实际接受才称已确认 |
| 支付 | 待支付、处理中、已付、失败、部分退款、已退款 | 与真实款项一致 |
| 履约 | 待发、部分发、已发、送达、异常 | 生成物流号不等于已揽收 |
| 售后 | 申请、审核、待寄回、处理、解决 | 每步有责任与依据 |
| 退款 | 待处理、已发起、处理中、成功、失败 | 请求、支付处理、到账说明分开 |

时间线显示可核实事件和更新时间，不猜测供应商未返回状态。
允许真实组合，例如部分已发货，另一件取消且退款处理中。
改单、改地址、取消等操作检查当前状态，发货后不继续保证可取消。

## 12. 配送、退换货与客服

付款前说明配送范围、费用、预计时效和分批可能。
跨境明确税费、进口责任与额外费用；无依据不承诺到手价或保证到达。
取消规则说明可申请时间、供应商确认要求及已发货后的处理。
退货说明资格、期限、地址、运费和商品状态条件。
瑕疵、错发、丢件、未收到商品与换货均需有实际处理路径。
部分退货需计算优惠、运费和税费，区分退款发起、处理与到账。
提交取消不等于已取消，等待供应确认时显示处理中。
统一界面不能承诺后台无法执行的统一无条件退换政策。
客服保留一个清楚入口，按商品、订单和责任方分配，并记录结果。
支付异常、拒单、逾期发货和退款失败都有升级负责人。
不让用户在多方之间自行猜测谁负责，平台协调能力需与承诺一致。

## 13. 运营能力分期责任表

| 能力 | 首个交易前 | 单供应商验证 | 多供应商扩展 | 必须指定角色 |
|---|---|---|---|---|
| 合同与授权 | 落实责任和地区 | 逐商品核查 | 逐供应商复核 | 商业负责人 |
| 商品与库存 | 同步及失效规则 | 有限人工核验可行并留痕 | 监控数据与异常 | 商品运营与供应联系人 |
| 接单与发货 | 履约规则与追踪 | 每单有责任人 | 状态映射、多包裹与异常 | 履约运营 |
| 客服售后 | 入口、时段、权限 | 人工闭环可接受 | 分派、升级、质量追踪 | 客服及升级联系人 |
| 支付退款 | 资金流与权限 | 实际退款并核对 | 部分失败与部分退款 | 支付运营 |
| 对账结算 | 费用与账期 | 逐单核对差额 | 按商家、期间和退款归集 | 财务或对账负责人 |

角色可兼任但不能空缺，表格不表示已经组建对应团队。
手工处理有容量边界和记录，不能描述为已自动接入。
逐供应商核实展示、报价、库存、预留、下单、取消、物流、退货和退款能力。
缺项说明可行替代及影响，核心交易无法闭环时不开放真实付款。

## 14. 对账与资料最小化

关联用户订单、供应商订单、支付尝试、退款和结算记录。
分清商品、运费、税费、折扣、支付费用、平台收入与供应商应收。
佣金、采购差价和支付费用依真实模式核算，不混为同一收入。
记录账期、退款扣回与差额，不覆盖历史数字制造账面一致。
首轮验证包含退款后的完整对账，不只核对成功付款。
资料收集与共享限于成交和履约需要，供应商仅取得其必要信息。
公开链接、日志和仓库不保存真实支付资料、凭据及不必要个人资料。
实际运营前明确访问权限、记录与保留期限，市场和税务条件按实核查。

## 15. 演示边界与验收

未接入真实交易时使用演示、收藏或选品清单等准确名称。
测试支付持续显示测试状态，不收集真实银行卡，不承诺库存与发货。
模拟结果称演示完成，不称购买成功；样例订单和物流标明示例。
外链按钮写明前往零售商购买，不把沙盒结果当供应商接单。

| 场景 | 可检查结果 | 阶段 |
|---|---|---|
| 匿名浏览与选品 | 未注册可用，保存边界清楚 | B 起 |
| 访客查单 | 正当用户可访问，猜号不能取得资料 | C 起 |
| 最终报价 | 规格、库存、运费、税费与总额一致 | C 起 |
| 成功交易 | 支付、接单、发货和订单一致 | C 起 |
| 重复与超时 | 重试、刷新、响应丢失不重复扣款或下单 | C 起 |
| 回调异常 | 重复、乱序、延迟不重复累计或错误倒退 | C 起 |
| 付款后拒单 | 通知、补偿、退款结果可追踪 | C 起 |
| 取消或退货 | 政策能执行，款项状态与记录一致 | C 起 |
| 唯一件竞争 | 不重复成交，占用到期正确释放 | 含唯一件前 |
| 多供应商失败 | 继续或取消遵守用户确认规则 | D 起 |
| 分批与部分退款 | 商品、包裹、费用及退款可对应 | D 起 |
| 对账 | 金额可解释，差额有负责人 | C 起 |
| 表述真实性 | 演示、来源、人物关系及交易状态准确 | 全阶段 |
