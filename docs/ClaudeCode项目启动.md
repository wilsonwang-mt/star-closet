## 在Mac上打开项目

1. **先准备本地仓库。** 如果已有独立的Claude专用克隆，可以直接使用；不要覆盖正在由Codex使用的目录。如果尚无独立克隆，可在Mac“终端”执行下面两行。这只是准备文件夹，不需要先使用Claude命令行。

   ```sh
   mkdir -p "$HOME/Projects"
   git clone https://github.com/wilsonwang-mt/star-closet.git "$HOME/Projects/star-closet-claude"
   ```

   只有克隆成功后再进行下一步。若目录已存在或命令失败，保留现有文件，让Claude先检查目录与Git状态，不删除后重试。`git clone`本身已创建仓库，不需要再次`git init`。

2. **打开Claude Mac App，进入Code。** 使用该页面提供的项目或文件夹选择入口，选择上面的本地仓库；若提供运行位置选项，选本机Mac环境。Finder选择目录时可用`⌘⇧G`输入`~/Projects/star-closet-claude`。若App创建自己的隔离工作目录，让它报告实际工作路径和分支。
3. **连接权限以实际会话为准。** 按App提示授予这个项目需要的目录访问。App登录与GitHub推送是两项独立状态；仓库读取成功不代表能推送。推送需使用Mac上已有Git认证，必要时走GitHub提供的浏览器登录，不把token粘贴到聊天或仓库。不要为此扩大到无关目录、关闭权限检查或修改仓库访问设置。
4. **粘贴下一节的首次指令。** 不需要手工上传每份PRD，让Code读取当前仓库文件即可。App若有名称字段，填`Star Closet`；若只有会话输入框，直接用启动指令完成交接。
5. **看实际交付。** 首轮应给出读取的需求版本、实际目录/分支、可执行任务及提交结果；仅说“已理解”不算完成。当前云端已准备交接材料，尚未替你创建Mac目录、登录Claude App或验证Mac端推送。

这里不写死App按钮名称：本轮无法访问Claude官方文档核实当前版本界面。目录、Git与交接方法不依赖具体按钮文案；若实际界面没有本地目录入口，应先核对App版本及本地Code功能是否可用。

## 协作与后续

- **Claude Code与Codex**：每人/每工具独立目录、独立任务分支；开始前同步，合并前重新检查main。不要让两个会话并行写同一个未提交文件。建议分工不等于人员已到位，任务负责人要由实际接手者更新。
- **本地权限与外部动作**：Git文档提交合并已有授权；App的本地目录访问、账户登录须由实际本机会话完成。仅授予当前任务所需权限，配置本地项目不包含额外付费、外部联系或仓库安全设置变更。
