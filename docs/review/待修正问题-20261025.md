## Q1 衣橱详情页缩略图行数不一致

- **用户原话**：“我发现某个衣橱详情页中，卡片中的‘所包含服装的缩略图’有的是一行，有的是两行。这会导致整个大卡片的高度不一致。请从专业角度进行思考，并给出解决方案。”
- **已知**：在 460px 宽的窗格里看 `/closet/C01`，6 张卡都是 6 件、两行，高度一致。还没找到用户看到的那一间和那个宽度。D73 把宽屏衣橱页网格从三列改成两列，卡片变宽，件数不同的卡片（例如 5 件和 7 件）更容易一张一行、一张两行。
- **待做**：逐个衣橱、在 390 / 768 / 1100 / 1440px 下统计每张卡的缩略图行数，确认触发条件后再定方案。可选方向：同一网格内所有卡片的缩略图区按最多件数预留同样的行数；或缩略图改成固定一行、超出时显示「+N」；或按卡片宽度让缩略图等分一行（`components/closet/ClosetExperience.module.css` 的 `.pieces` / `.thumbs`）。
- **验收**：同一排卡片高度一致，缩略图不被裁切，中英文、手机与桌面都检查。

## Q2 试衣间「登录 / 注册」按钮背后的直角底板

- **用户原话**：“为什么登录/注册按钮背后的背景，出现如此锐利的形状？”（截图：浅色主题、桌面，`/fitting-room` 未登录）
- **原因**：按钮放在 `.cta-bar` 里。它是吸底操作条，`::before` 是一块渐隐底板（`app/app/globals.css` 第 313–316 行：`inset: -20px -20px 0`，只做从上到下的渐变，透明 → 72% 背景色 → 88% 背景色）。这块底板本来用于手机上内容滚过操作条时托住按钮；但页面内容很短、操作条没有吸到屏幕底部时，它就停在页面中间，变成一块浮在场景图上的矩形：左右两边是硬边，底边在 88% 不透明处直接截断，于是看起来是锐利的直角形状。浅色主题下底板颜色和场景图差异更明显。
- **同样用到 `.cta-bar` 的地方**：`app/fitting-room/page.tsx`（未登录与空状态两处）、`app/bag/page.tsx`、`app/bag/BagList.tsx`、`app/profile/ProfileForm.tsx`，都要一起看。
- **修正方向**（择一或组合）：
  1. 只在操作条真正吸底时显示底板：用滚动驱动的状态（`@container scroll-state(stuck: bottom)`，Safari 不支持时要有退路），或用 IntersectionObserver 给 `.cta-bar` 加 `data-stuck`，未吸底时不画底板。
  2. 底板改成没有边缘的形状：横向撑满视口（`left: 50%; width: 100vw; translate: -50%`）并一直渐隐到视口底部，或给 `::before` 加四周羽化的 `mask-image`，避免出现竖直硬边与截断的底边。
  3. 内容不长的页面（未登录、空状态）不用吸底条，按钮直接跟在说明文字下面。
- **验收**：深浅主题、手机与桌面、中英文下，未吸底时按钮背后没有可见的矩形；手机长页面滚动时，吸底按钮仍然有底板托住、文字清楚。

## Q3 首页手机端的横向筛选条

- **用户原话**：“这个横向滚动的筛选条，不应该支持拖拽，并且在手机端，这个筛选出现在首屏底部。并不是一个很合理的页面布局。因为这里的选择影响到了上方会展示的是哪一类。你思考一下，如何优化。”（截图：英文、手机、首页轮播下方，「Browse all 10 closets」之下）
- **现状**：`components/home/ClosetCarousel.tsx` 的 `renderFilters("index")`，样式 `.filters` / `.filtersIndex`（`ClosetCarousel.module.css`）。一行横向滚动的标签：全部、女装、男装、中性 | 风格主题、穿搭博主、个人主理人、品牌主题；两端渐隐，超出部分要横滑才能看到。D51 把它从手机首屏移到切换按钮下方（首屏用 AI 对话定位）；桌面仍在标题右侧。截图里第一个「全部」不在视野内（滚出左侧或被渐隐遮住），也要一并确认。
- **问题分析**：
  1. **控件在它控制的内容下面**：点了筛选，变化发生在上方的轮播里，人的视线和手指都在下面，往往看不到结果，只看到 01 / 10 变成 01 / 02。正常的顺序是「先选范围，再看结果」，筛选应该在结果上方，或者以浮层形式出现、选完关掉就看到结果。
  2. **横向滚动藏掉了一半选项**：衣橱类型在屏幕外（截图只露出「STYLE CL…」），用户不知道还有哪些可选。
  3. **两条横向手势叠在一起**：正上方的轮播本身可以左右拖动，下面又是一条可以横滑的筛选条，手指容易滑错区域，页面纵向滚动时也容易误触横滑。
  4. **数量小**：首页只有 10 间衣橱，筛完常常只剩一两间，轮播的意义变弱；完整筛选在全部衣橱页 `/closets`（D71，性别、类型、风格三组，条件写进网址）已经有了。
- **修正方向**（需要用户选）：
  1. **推荐：首页不再就地筛选，改成「按类型浏览」入口**。轮播始终展示全部衣橱；「Browse all 10 closets」下方放一组换行排列、不滚动的入口（女装、男装、中性、风格主题、穿搭博主……），每个都跳到 `/closets` 并带上对应条件（例如 `/closets?gender=女装`）。选择和结果在同一页、同一视野里，也保留了 F01 首页五类发现入口；首页不再有第二条横滑。桌面标题右侧的筛选同样改成入口或去掉。
  2. **就地筛选，但放到轮播上方，用一个「筛选」按钮打开底部浮层**：按钮显示已选数量；浮层里两组标签换行排列，选完关闭浮层就看到轮播更新。保留首页筛选功能，但首屏多一个按钮（D51 当初就是为了让首屏更干净才移走筛选）。
  3. **只做最小修正**：标签改成换行排列、不再横滑，位置不变。解决不了「控件在结果下面」的问题，不推荐。
- **与其他事项的关系**：首屏标题区探索（`explore/home-hero`，已暂停）里三个方案也把筛选放在切换按钮下方，同样有这个问题；以后恢复首屏方案时要按这里的结论一起改。选 1 或 2 都会改变 D51 中筛选位置的约定，需要用户确认。
- **验收**：手机与桌面、中英文下，筛选的选项一眼看全、不需要横滑；用户做出选择后，结果就在视野里；首页只有轮播一处横向手势。

## Q4 全部衣橱页的筛选层级

- **用户原话**：“这里其实分了好几类筛选，但是这些筛选平铺出来，有些混乱，有没有办法做到，用户当前界面先看到最常用的筛选项，展开后，或者唤起 filter 窗口后，再去做筛选呢？”（截图：英文、手机、`/closets` 标题下方的两行筛选）
- **现状**：`components/home/ClosetDirectory.tsx` 与 `ClosetDirectory.module.css`。第一行把「全部、性别（女装 / 男装 / 中性）| 衣橱类型（风格主题、穿搭博主、个人主理人、品牌主题）」放在同一条横滑里，第二行是「风格」加最多 10 个风格标签，也是横滑。三类条件没有分组标题（只有风格行有一个小标签），超出屏幕的部分被渐隐截断（截图里的 UNISEX、STYLE 被切），已选条件只靠一个小圆点表示。条件写进网址（D71），这一点要保留。
- **问题分析**：
  1. 三类条件的地位不同却平铺在一起：性别是第一层决定（时装电商的顶层导航几乎都是女装 / 男装），衣橱类型和风格是进一步细化，混在两条横滑里，用户分不清哪些是一组、能不能同时选。
  2. 两条横滑都会截断选项，用户看不全有哪些可选，手指也容易和页面纵向滚动打架。
  3. 已选了哪些条件、怎么单独取消，不够明显。
- **修正方向（推荐）**：参考时装与购物 App 常见的「顶层快捷项 + 筛选面板」（Refero：On「View results (51)」、Pinterest、Klarna「Show 1」、TikTok Shop 的底部筛选面板）。
  1. **页面上只露出一行最常用的**：性别分段「全部 / 女装 / 男装 / 中性」（4 项，一行放得下，不横滑），右侧一个「筛选」按钮，带已选数量（例如「筛选 · 2」）。
  2. **点「筛选」唤起面板**：手机从底部升起，桌面从右侧滑出。面板里按组排：衣橱类型、风格（以后还能加城市、预算等），每组有标题，标签换行排列、不横滑；每个选项旁显示这个组合下还有几间（例如「极简 2」），没有结果的置灰。底部固定两个按钮：「清除全部」和「查看 N 间衣橱」（N 随选择实时变化），点后关闭面板、列表更新。
  3. **已选条件可见、可单独取消**：快捷行下方显示已选的条件小标签（例如「穿搭博主 ×」「极简 ×」），点 × 去掉，旁边「清除」。
  4. 网址参数照旧（`?gender=…&type=…&style=…`），刷新、分享、返回都能还原；首页 Q3 的「按类型浏览」入口跳过来时，条件直接是选好的状态。
  5. 面板按对话框实现：打开后焦点进入面板，Esc 关闭并把焦点还给「筛选」按钮，手机上可以下拉关闭。
- **可再讨论**：哪一类算「最常用」，目前按行业惯例定为性别；以后有了点击数据可以换成用得最多的那一类。桌面空间够，也可以继续平铺但按组加标题；为了两端一致，建议同样用「快捷行 + 面板」。
- **与其他事项的关系**：和 Q3 一起做，首页入口与本页筛选用同一套条件和网址。
- **验收**：手机与桌面、中英文下，页面上只有一行快捷筛选和一个筛选按钮；面板里分组清楚、选项不截断、显示结果数；已选条件一眼可见、可单独取消；网址还原正常；键盘可操作。

## Q5 信息架构：男女、为家人购买、注册前探索

- **用户原话**：“信息架构层面需要你思考一下，我们会面对复杂的使用者情景：男性、女性，主力可能是年轻人或者中年人。但是他们又可能会给家人买衣服。还有就是不管哪类用户，他们来到首页，创建账户之前，都可能产生探索的需求，其实我们的男性，女性的选择的功能，在首页上，并不是很明显的。”
- **现状**：
  - 性别只是衣橱、搭配、单品上的一个属性（女装 / 男装 / 中性），在首页是筛选条里的几个标签（手机上在轮播下方，见 Q3），在 `/closets` 和其他条件平铺在一起（见 Q4）；搭配区「按场合，整套穿走」、AI 对话都不知道用户在为谁挑。
  - 档案页没有性别或「为谁购买」的字段；访客可以完整浏览公共内容（PRD 访客权限、信息架构 §未登录）。
  - 供给偏女装：衣橱 女装 7 / 男装 2 / 中性 1，搭配 42 / 12 / 6，单品 152 / 38 / 19（`data/catalog.json`）。
  - 需求文档里没有「为家人购买」的定义。
- **分析**：
  1. 「性别」要分成两层：一是**商品属性**（这件是女装、男装、中性），二是**这次在为谁挑选**（自己、伴侣、父母……）。为家人买衣服时，用户本人的性别和要看的衣服无关，所以界面上的入口应该问「为谁选」，而不是「你是男是女」。
  2. 时装电商的做法是把「女士 / 男士（/ 童装）」放在最顶层，一直可见，并记住上次的选择：FARFETCH 头部左上「Womenswear / Menswear / Kidswear」，SSENSE 导航第一项「Menswear / Womenswear / Everything else」，COS、Zara 也是「女士 / 男士 / 儿童」打头。SEEN. 现在把它藏在筛选里，首页又以「谁的衣橱」开场，男性访客第一眼看到的多半是女装衣橱，容易以为这里不是给他的。
  3. 注册前的探索不该被打断：选择记在浏览器里（cookie），不需要账户；登录后可以并入档案。
  4. 年龄不适合作为入口或筛选：问年龄有冒犯感，「中年」也不是风格。年轻人与中年人的差别用风格、版型（宽松 / 修身）、场合（商务、通勤、婚礼宾客）和主理人的多样性来覆盖。
- **建议结构**：
  1. **全站「为谁选」开关**：女士 / 男士 / 全部。桌面放在导航里（主链接左侧或品牌旁），手机放在首屏卡片上方一行（与 Q3、Q4 合并成同一个控件，不再另放筛选）。选择后首页轮播、「按场合，整套穿走」、全部衣橱页的默认条件、AI 对话的推荐都跟着变；中性的衣橱与搭配在两边都出现。选择写进 cookie，访客也能记住；网址参数仍可覆盖（分享链接时）。
  2. **第一次来访**：默认「全部」，开关本身要显眼；可选一个轻量提示「你在为谁挑选？女士 / 男士 / 都看看」，一行、可忽略，不用弹窗挡路。AI 对话里说「给我老公挑一套婚礼宾客」时，也可以顺带切换。
  3. **为家人购买（登录后）**：档案里加「家人」——称呼、为他（她）挑选的性别、尺码、预算、风格偏好；「为谁选」开关里多出这些人（例如「为爸爸选」），推荐按他（她）的尺码与偏好走；试衣间、购物袋按人分组，下单时可选收货人。数字分身试穿默认只给本人；给家人试穿涉及他人身体影像，需要对方同意，第一版不做，只按尺码推荐。
  4. **童装**：目前没有供给，开关里先不放，以后有童装衣橱再加第三项。
- **风险与前提**：男装供给只有 2 间衣橱（加中性 3 间）、18 套搭配，选「男士」后首页会明显变少——需要同时补男装主理人，或在男士视图里把搭配区放在衣橱轮播前面。这是内容与招募问题，不只是界面。
- **需要用户拍板的产品决定**：①是否采用全站「为谁选」开关、首访默认「全部」还是先轻问一句；②「家人档案」是否进入当前范围；③男装供给的补充计划。定下后补决策记录编号。
- **用户答复（2026-10-25）**：①“你先去做探索，我先不选方向”——做「为谁选」开关的几种放法预览，不定方向；②家人档案先不做；③同意补充男装主理人（D74）。
- **与其他事项的关系**：会决定 Q3（首页筛选条）、Q4（全部衣橱页快捷筛选）的最终形态——快捷筛选那一行就是这个开关；也会影响已暂停的首屏标题区探索（`explore/home-hero`），首屏要给这个开关留位置。建议先定 Q5，再一起做 Q3、Q4。
- **验收**（做的时候）：访客在首页一眼能找到并切换女士 / 男士；切换后首页、全部衣橱、对话推荐一致；刷新、换页、下次来访仍记得；中性内容两边都在；手机与桌面、中英文都检查。
