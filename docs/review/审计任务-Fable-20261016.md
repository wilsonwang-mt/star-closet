## 2. 工作方式

1. **真的跑起来看，不只读代码。** `cd app && npm install && cp .env.example .env.local`（填 `BETTER_AUTH_SECRET`）`&& npm run db:setup && npm run dev`。用 Playwright（受管 Chromium）或可用的浏览器工具，在 **375×812** 与 **1440×900** 两种视口走完核心路径并截图；深浅两种主题各一遍；开启 `prefers-reduced-motion` 一遍；用 Slow 3G 节流看一遍首屏与路由切换；录一段性能 trace 看长任务与掉帧。做不到的项目如实写进「未能验证」，**不要用推测冒充测量**。
2. **证据优先。** 每条发现附 `文件:行号`、截图路径或测量数值。没有证据的只能标为"品味判断"。
3. **三种判断分开标注**：事实（可复现）／推断（有依据但未复现）／品味判断（给出参照页面让我能对齐）。
4. **不要被文档的自我评价带着走。** 交付记录与 README 由做事的会话自己写，里面"已走通""已打磨"是声称。
5. **独立于 Opus 的决定。** 如果某个已做的设计或技术决定你认为是错的（哪怕已经"定稿"），直说，并给出替代方案与代价。但请区分"错了"与"我会不一样地做"。
6. **先看整体，再看细节。** 先用 2 分钟当一个第一次打开的评委走一遍，记录直觉反应；再逐维度审。两者结论如果矛盾，把矛盾写出来。
7. **已知问题不重复发现**，除非你认为其严重度被低估或根因判断错了。

## 3. 审计维度

每个维度给出：**评分（1–10，10 = apple.com 新品页 / 一线时尚电商水准）**、关键发现、具体建议。不要为了凑数每个维度都写一样多；哪里问题大就在哪里深挖。

### A. 视觉语言
- "电影感买手店"是否真的成立：画面负责氛围、界面只负责信息，这个分工在每一屏都守住了吗？
- 与 `电影感样稿v5.html` 并排比对：字号、字距、行高、玻璃质感、暗角、光束、颗粒、金箔流光——应用里哪些被稀释或丢失了？
- 两种主题是否各自完整成立，还是浅色只是"把深色反过来"（规范 §3 要求场景图随主题切换）。
- 层次与留白：每屏是否只有一个主角；装饰是否出现在卡片之外（规范 §2 禁止）。
- 色彩：香槟金的使用是否克制且一致；对比度（浅色香槟文字已调至 AA，核实其他组合）。
- 字体：三款字体的职责是否清晰（Bodoni 只用于刊头 / 引题 / 编号 / 价格）；中英混排的基线、字重、标点是否讲究。
- 品牌表达：`STAR CLOSET` 刊头、刊号式副刊头、favicon / manifest 图标 / 主题色是否成体系。

### B. UI 构建质量
- 组件一致性：按钮、胶囊、玻璃卡、列表行、徽章、输入框在各页是否同一套；有没有同一语义多种实现。
- tokens 纪律：`tokens.css` 之外是否有硬编码颜色 / 阴影 / 圆角 / 动效曲线（grep 一遍 `globals.css` 与 `*.module.css`）。
- 间距系统：有没有统一的 spacing 尺度，还是逐处手调。
- **状态完整性**：每个交互元素的 hover / focus-visible / active / disabled / loading / 选中态；每个页面的 empty / error / loading / 部分加载 状态。缺哪个列哪个。
- 响应式：375、390、430、768、1024、1440、1920 各看一眼；宽屏是否只是把手机版放大；`--sc-col-wide` 对齐规则是否全站一致。
- 细节放大看：0.5px 描边在非 Retina 上如何；玻璃层叠不超过两层；圆角与内容圆角的嵌套关系；图片裁切焦点。
- 表单：登录 / 档案 / 同意卡的输入体验、错误提示位置、键盘类型、自动填充。

### C. 用户体验与流程
- 第一次打开：用户 5 秒内能明白"这是什么、我能做什么"吗？"走进谁的衣橱"这个心智是否被界面讲清楚。
- 核心路径逐步摩擦点：首页选择 → 走进衣橱 → 挑搭配 → 改编 → 加入试衣间 → 外链购买。每一步的决策负担、等待、返回与状态保持（`?c=`、sessionStorage、滚动定位）。
- 登录时机：在哪一步被要求登录？是否打断了最有价值的瞬间？匿名能走多远？
- 一句话改编：输入引导（示例句、语音入口的可见性）、10–13 秒等待的心理管理、结果可信度的呈现、"没听懂 / 没变化"的提示态、逐件替换的可发现性。
- 试衣间：保存后的去向、购物清单与外链的信任感、空试衣间。
- 档案与 3D 形象：同意卡的清晰度与压迫感、三张照片上传的指引、生成等待、失败与重试、删除的安全感。隐私承诺在界面上是否可感知而非只在文档里。
- 导航与信息架构：悬浮胶囊的收起 / 出现是否会让用户找不到入口；手机菜单；当前位置感。
- 免责类标注（"AI 生成示意""合身未验证""虚构示例"等）已按决策 D48 从比赛版界面移除（见 AGENTS.md「内部比赛版界面去提示决定」）。不要建议加回来；只在发现文案宣称了**未实现的能力**（精准还原本人、尺寸准确、保证合身、站内支付）时指出。

### D. 动效与交互（对标规范 §7.1）
逐一审：首页浅弧轮播（拖拽跟手、速度吸附、打断、侧卡透视 / 模糊 / 变暗的连续性、姓名与按钮不倾斜）、走进衣橱共享元素过渡（约 925ms；文字先淡出再浮起；返回反向；视频定格续播；>700ms 超时降级）、衣橱页滚动叙事（粘性场景 + scroll-driven）、改编等待与结果（光束、淡出落入回弹、总价滚动）、3D 查看器（落下回弹、自转、惯性、复位）、导航收起 / 出现、主题切换。
- 每个动效回答五个问题：有物理依据吗？能被打断吗？连续还是跳切？是否只动 transform / opacity / filter？减弱动态下的退化是否得体？
- 节奏：整体是否存在"动得太多"或"该动的没动"；是否有为动而动的装饰。
- 弹簧参数（`lib/motion.ts`）是否统一且合理；CSS `linear()` 采样与 Motion 参数是否一致。
- 真机 / trace 测得的掉帧、长任务、layout thrash，列出来源。
- Firefox 覆盖层路径既然未实测，请实测或明确说明无法实测。

### E. 网站 Loading 与首次进入体验（重点）
现状：只有 `app/**/loading.tsx` 的路由级骨架，没有站点级首次进入体验；首页 `force-dynamic`，字体 `preload: false`，场景视频按需加载。
- 先测量：冷启动首屏到可交互的时间线（HTML → 字体 → 首张海报 → 视频可播 → hydration → 轮播可拖）。哪一段最长、用户在这段看到什么。
- 评估现有骨架：与真页面是否同位、是否跳动、是否出现太快（闪一下）或太久。
- **提出 2–3 个"更具互动感的 Loading / 进入仪式"概念**，推荐一个，并给出：分镜（逐帧描述）、状态机（哪些真实事件驱动进度：字体就绪、海报解码、视频 canplay、hydration 完成）、技术路径（放在哪一层、与 View Transition 和规范 §7「虚焦暗场推到清晰」的 3s 场景进场如何衔接）、手机资源预算、减弱动态下的退化、可跳过策略。
- 硬约束：**不做假进度条**；不增加感知等待（有内容就不应被 loading 挡住）；只在冷启动 / 首次访问出现，站内路由切换沿用共享元素过渡；不与品牌气质冲突（杂志、电影、克制）。
- 顺带评估 PWA：`manifest.ts`、图标、iOS 添加到主屏的启动画面与状态栏表现。

### F. 性能与感知性能
- Core Web Vitals（LCP / INP / CLS）在两种视口的实测或估算；字体加载策略（FOIT / FOUT、`preload: false` 的后果）；视频策略（海报、`preload`、只播可见段）；图片格式与尺寸（`public/catalog/`、`public/scenes/`）；3D 资源体积；首页 `force-dynamic` 的必要性；bundle 体积与分包；预取策略（开发模式不预取导致的"首次进入慢"在生产是否消失）。
- 主题切换 / SSR 是否有闪烁（FOUC）。

### G. 可访问性
对比度、焦点顺序与可见性、键盘可达（轮播、菜单、3D 查看器、改编）、屏幕阅读器语义（`role="status"`、`aria-current`、`aria-busy`）、触控目标 ≥ 44px、动态减弱、表单标签与错误关联、视频无字幕是否可接受（装饰性）、语言标注。

### H. 文案与内容
微文案是否与"杂志感"一致；按钮动词；错误信息是否说人话；空状态是否有引导；中英混排与标点（全角 / 半角、间距）；诚实标注的措辞是否既合规又不扫兴；页面标题 / description / OG 元信息。

### I. 功能完整性与边缘情况
空目录、衣橱无视频 / 无头像、断网 / 弱网、AI 调用失败或超时、登录会话过期、极长文本（昵称、风格说明）、极端视口、iOS Safari（`100dvh`、safe-area、视频自动播放策略、橡皮筋滚动、输入框聚焦缩放）、Android Chrome、回退 / 前进缓存（bfcache）、多标签并发、404 的 HTTP 状态 200 问题的影响评估。

### J. 跨浏览器与设备
Safari iOS、Chrome Android、桌面 Chrome / Safari / Firefox、触控板横滑、外接鼠标滚轮。列出各路径的实测或"未测"。

### K. 代码层面影响体验的结构问题
只看会影响体验与后续迭代速度的：CSS 组织（`globals.css` 517 行 + module）、动效参数是否散落、724 行的轮播组件是否该拆、SSR / CSR 边界、状态管理、重复实现、死代码、注释与实现不一致。不做泛泛的代码审查。

### L. 演示与比赛就绪
距截止不到 24 小时。评委 2 分钟会看什么？当前演示路径的"哇时刻"在哪、够不够强？哪些缺口会在演示中暴露？给出"截止前必须 / 截止前最好 / 截止后"三档清单，以及一条推荐的演示脚本（每步标注实操 / 预录 / 概念）。

### M. 发散：我没问但你认为该做的
例如但不限于：签名时刻（一个让人记住的交互）、声音与触觉（是否适合、怎么克制地用）、分享与社交（把改编结果分享出去）、个性化（记住风格偏好后首页如何变化）、品牌与命名（Star Closet 作为工作名的表达）、多语言、无障碍之外的包容性（体型、肤色在示意素材中的表达）、数据与隐私的可感知设计、对 3D / 试穿"还原度未验证"的诚实表达方式、把 10–13 秒的 AI 等待变成内容而非等待。每条说明：为什么值得、代价多大、现在还是以后。
