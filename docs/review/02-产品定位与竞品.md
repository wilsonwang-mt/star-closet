# 评审报告 02 · 产品定位与竞品

2026-10-15 15:50–16:00（UTC+8）。评审方式：AI 评审 agent 只读审阅基线 `4c8275c` 文档并做网络检索，未改动文件。竞品信息来自网络，部分为厂商或第三方页面；本文不是用户决定。

## 1. 定位核心问题

- **同时铺开四门生意**：PRD §1.2 五个入口、§6 F01–F15 十五个模块、§7.4 四套收入账本，等于同时做内容平台、AI 衣橱、电商导购、创作者 SaaS。冲刺 §1.2 记录代码为 0，§7「必须保留」仍有 7 项。
- **目标用户未定**：PRD §1.1「首批客群、市场与币种未定」，商业模式 §14 第 1 条仍为待决。“大众消费者”不算目标用户。
- **名称冲突**：PRD §1 说不再限定明星，但 §1.2 首行仍是明星衣橱、D32 是明星门票；产品策略 §2 写明没有确认真实人物合作；研究摘要提到 2015 年有同名应用。新愿景重心是“自己”，Star 把重心拉回“别人”。

## 2. 竞品与楔子

- **试穿已不稀缺**：
  - 试穿 API：FASHN、Kling 约 0.07 美元/张（fal.ai、CometAPI 页面，非官方价目，待核实）。
  - Zara App 用自拍加全身照生成试穿，覆盖市场待核实。
  - 淘宝千问可上传全身照试穿，实测效果近似标准身材。
  - Google Doppl（2025-06 上线，仅美国）与 WearWow 已能“截图博主穿搭 → 试穿 → 跳转购买”。
  - 结论：“灵感截图 → 穿到身上”别人已经做了，不能当差异点。
- **空位**：大平台只试自家单品；Doppl、WearWow 只试一张图，没有策展，也不按用户约束改写。Alta（2025-06 种子轮 1100 万美元）偏用户自有衣橱。优衣库、小红书官方、得物现状待核实。
- **楔子：整套风格的本人化改编**——把顾问或博主的一整套搭配，按用户的预算、场合、身形拆成买得到的平替，穿在用户身上对比，并说明为什么适合。唯一确认的供给是 D33 时尚顾问，楔子要建在她身上。

## 3. v0.4 建议（假设中文市场，待定）

- 一句话定位：把你收藏的穿搭，改成适合你、买得起、能上身的那一套。
- 首要用户：20–30 岁、常在小红书收藏穿搭却很少下单的女性。
- 首要场景：看到喜欢的一套，想知道“我穿什么样、预算内怎么买”。
- 核心价值：从“像她”到“适合我”，一次给出改编后的组合、本人上身图和总价。
- 黑客松版：顾问预置 20–30 套搭配、约 100 个商品；上传自拍 → 选一套 → Agent 拆单品 → 一句话改约束（“800 以内，换平底鞋”）→ 2D 试穿对比 → 外链购买；页面标明“2D 生成”。
- 长期版：博主发布“可改编搭配”，第一条收入只做按成交分佣（CPS）；个人风格档案免费积累，订阅待验证后再考虑。
- 暂缓（不删需求）：3D 衣橱舞台硬门槛（D11）、3D 本人形象与实时试穿（D26）、五类入口（D21）、建橱 Agent 与团队协作（D22/D23）、付费私密衣橱（D29）、粉丝门票（D32）、入驻费（D30）、站内支付与分账。

## 4. 矛盾、过度承诺与过度对冲

1. 定位有四种说法：PRD §1、产品策略 §1、README 首段、定位调整开头；愿景 §1 又是另一句。
2. 新愿景核心被排在最后：D26 要求准确三维化身与实时，产品策略 §9 却把 3D 本人形象排在 P3。
3. 收入线矛盾：商业模式 §1 主张只做一条收入线，PRD §7.4 却把四套账本细化到退款冲回。
4. 文档锁死取舍：PRD §10「这不是用户已批准的功能裁剪」，定位调整 §2「不能因技术难度…改记为未提出」。
5. 对冲太密：“不能”在商业模式出现 19 次、PRD 16 次；“建议”在产品策略 14 次，读不出团队押注什么。
