# 英文版设计审计与首页优化（D71）· 2026-10-24

依据：用户 2026-10-24 原话“我发现英文版本，看起来页面内容有些过于紧凑，缺乏美感。你去做一次 Design Audit 来判断，使用的字体，字号，以及UI设计，如何优化才能够有更好的设计美感。做完之后，我需要你把首页做一次优化，优化的区域主要是考虑到 顶部的导航，以及页面的第二部分内容，也就是 衣橱列表。”随后补充：“同时要考虑一下，在新的方案中，用户是否仍然可以前往 衣橱列表页，进行筛选。”

截图在 [home-commerce-shots/](home-commerce-shots/)：`before-*` 是改前，`after-*` 是改后。

## 结论

- 英文显得“紧”，主要不是间距不够，而是**字**：正文用的是思源黑体 Light 300 自带的西文字形，12–13px 下笔画细、字面窄；又沿用了为中文设计的 0.08–0.22em 宽字距。英文字母本身有字间节奏，再加宽字距，就显得散而挤；标题只有 20px，撑不起首屏。
- 已改：英文正文与界面字换成 **Instrument Sans**（SIL OFL，自托管拉丁子集 37KB），字号令牌整体上调一档，英文统一回到正常字距；英文标题继续用 Bodoni Moda 并放大、字距收紧。
- 首页第二部分原来是 10 行与轮播完全重复的衣橱列表，不产生任何行动。换成 **「按场合，整套穿走」**：按场合切换，每个场合一套主推（大图 + 逐件单品、价格、一键试穿 + 整套加入试衣间 / 购物袋），再加同场合的另外三套。
- 衣橱列表没有消失，变成独立的 **全部衣橱目录页 `/closets`**：网格 + 性别、衣橱类型、风格筛选，筛选写进网址；导航“衣橱”指向它，首页轮播下方也有入口。
- 导航新增“搭配”（锚点到首页新区块）与“搜索 / 问造型师”（打开悬浮对话），主链接与工具图标之间加细分隔线。
- 线上验证记录的 8 处英文排版问题全部处理（第 1 处随旧列表移除）；本次实测又发现并修好衣橱页搭配卡在英文下溢出。

## 二、首页第二部分该放什么

### 回看项目目标

- 定位（PRD §1）：主理人和品牌策展、AI 帮助搭配的大众时尚平台——发现审美，把服装带进个人试衣间，以自己的形象查看，再完成可信选购。
- 用户定的核心亮点（D67）：“浏览的过程中，可以直接一键试穿……一键试穿应该非常明显的功能入口”；平台主打（D59）：用本人形象试穿并判断合身；站内下单（D57）。
- 首页（F01）：浅弧主卡保留，扩展五类发现入口；AI 对话负责帮用户定位（D52、D66）。
- 商业模式（商业模式与平台运营 §1）：长期收益取决于复访与净成交，“不取决于衣橱数量本身”。

### 原列表的问题

首屏轮播已经回答了“走进谁的衣橱”。第二部分再列一遍同样的 10 间衣橱，用户往下滑只看到重复信息；没有价格、单品，也不能试穿或加入试衣间，离成交还隔着“进衣橱 → 选搭配”两步。

### 候选与取舍

| 候选 | 为什么不选 / 为什么选 |
| --- | --- |
| 新品单品网格 | 单品是零散的，SEEN. 的独特价值是“主理人搭好的整套”，单品网格与普通电商无异 |
| 主理人 / 衣橱列表（原方案） | 与首屏轮播重复；保留到 `/closets` 目录页并提供筛选 |
| 品牌墙 / 合作方 | 目前没有真实品牌合作，不能虚构供给（PRD §1.1） |
| 数字分身推广横幅 | 是主打能力，但单独一块横幅不产生购买行动；本次把“试穿”放进每件单品上，横幅留作后续 |
| **按场合整套（选用）** | 对应用户最直接的需求“我明天需要穿什么”（PRD §1.1）；整套是 SEEN. 的核心单位；每件单品就地一键试穿（D67）、整套加入试衣间 / 购物袋（D57、D67），一屏完成从看到试到买；场合也是 AI 对话的主要线索，区块右上角直接接“问造型师” |

结构参考 Zara 首页的 “LOOK · N items” 模块（大图 + 一排单品，每件带价格与操作），视觉沿用 SEEN. 自己的深色玻璃系统。

### 实现

- 场合：周末、通勤、约会、聚会、旅行、婚礼宾客（目录 v0.2 里搭配最多、最贴近日常的六个，中文原值，显示时翻译）。
- 每个场合最多 4 套：在主理人之间轮流挑，同一间衣橱不连着出现；各场合的主推不重复（`lib/home/edit.ts`，4 项测试）。
- 一键试穿与加入试衣间复用衣橱页的 `QuickTryButton`、`LookActions`，行为一致；本地没有 `FAL_KEY` 时试穿按钮不显示（与衣橱页相同）。
- 键盘：场合标签按 WAI-ARIA tabs 实现，左右方向键、Home / End 切换。

### 衣橱列表去哪了：`/closets`

- 网格展示全部衣橱（手机两列、宽屏三列）：场景图、主理人头像、类型、衣橱名、简介、搭配数、风格。
- 筛选：性别 × 衣橱类型（F01 五类发现入口）一行，风格一行；组合后没有结果的选项置灰；条件写进网址（`?gender=男装&style=极简`），刷新、分享、返回都能还原。
- 入口：导航“衣橱”（衣橱页、搭配页也算这一栏）；首页轮播下方“查看全部 10 间衣橱”。首页原有的筛选保留，只作用于轮播。

## 三、导航

- 主链接：衣橱（→ `/closets`）· 搭配（→ 首页 `#looks`）· 试衣间 · 我的档案 / 登录。
- 工具：搜索 / 问造型师（打开悬浮对话，≥900px 显示；手机右下角常驻对话入口）· 购物袋 · 语言 · 主题，与主链接之间加 .5px 分隔线。
- 宽度沿用首页宽栏（与中央卡片对齐）；640–899px 收窄链接内边距。实测 640、768、900、1024、1280px 中英文都不溢出。

## 四、参考与决策

参考（Refero）：SSENSE、FARFETCH、Sneak in Peace 的完整风格规范；Zara 首页 “LOOK” 模块、SSENSE 首页的实际页面。

参考锁定：

- 主方向：SEEN. 现有视觉系统（视觉规范 v5）——深色电影感背景与环境场景、玻璃面板、香槟金只用于主操作、金箔只用于编号与总价、Bodoni 标题。
- 借用：Zara 的整套模块结构；SSENSE 的字体对比（大号衬线标题字距收紧 + 正常字距的实用型无衬线小字）与 64–112px 的区块间距。
- 不采用：参考站的白底、直角零圆角（与 SEEN. 的玻璃系统冲突）；英文宽字距；十行相同的列表。

| 决定 | 来源 | 理由 |
| --- | --- | --- |
| 英文界面字 Instrument Sans 400/500 | SSENSE、Sneak in Peace、FARFETCH 都用正常字距的怪诞体做界面字 | 与 Bodoni 标题形成对比，小字号清晰 |
| 英文字距 0–.02em，小号大写 .06em | 同上；字体排印常规 | 英文字母自带间距，宽字距只适合全大写短标签 |
| 首屏标题 24/28px、区块标题 32/42px | SSENSE 标题 38–56px | 首屏要给轮播留高度，所以首屏标题只放大一档，区块标题放开 |
| 区块间距 72 / 112px | SSENSE 64px、FARFETCH 48–72px | 首页两部分分清层次 |
| 整套模块：大图 + 逐件单品 + 总价 + 整套操作 | Zara “LOOK” 模块 | 整套是 SEEN. 的核心单位，一屏完成看、试、加入 |
| 场合标签：文字 + 细下划线 | FARFETCH 分类条 | 低装饰，手机可横滑 |
| 香槟金只给“整套加入试衣间”，金箔只给总价 | SEEN. 视觉规范 | 保持主操作唯一 |

## 六、后续建议

1. 英文长段落（搭配说明、衣橱简介）改用 Instrument Sans，标题保留 Bodoni（S1）。
2. 试衣间、档案、数字分身页按新令牌逐页复核英文层级（S2）。
3. 首页加一块数字分身推广位：没有分身的用户引导去建立，有分身的直接展示“穿在你身上”。
4. 主理人入驻入口（供给侧，双边平台）放在页脚或档案页，首页暂不占位。
5. 做 `/looks` 全部搭配页（按场合、预算、性别筛选），导航“搭配”届时改指向它。
