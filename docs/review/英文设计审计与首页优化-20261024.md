# 英文版设计审计与首页优化（D71）· 2026-10-24；字体统一（D72）、编辑大字（D73）· 2026-10-25

依据：用户 2026-10-24 原话“我发现英文版本，看起来页面内容有些过于紧凑，缺乏美感。你去做一次 Design Audit 来判断，使用的字体，字号，以及UI设计，如何优化才能够有更好的设计美感。做完之后，我需要你把首页做一次优化，优化的区域主要是考虑到 顶部的导航，以及页面的第二部分内容，也就是 衣橱列表。”随后补充：“同时要考虑一下，在新的方案中，用户是否仍然可以前往 衣橱列表页，进行筛选。”

截图在 [home-commerce-shots/](home-commerce-shots/)：`before-*` 是 D71 改前，`after-*` 是 D71 改后（当时英文标题仍是 Bodoni）；`d72-before-*` / `d72-after-*` 是字体统一前后，见 §七；`d73-*` 是编辑大字落地后，见 §八。

## 结论

- 英文显得“紧”，主要不是间距不够，而是**字**：正文用的是思源黑体 Light 300 自带的西文字形，12–13px 下笔画细、字面窄；又沿用了为中文设计的 0.08–0.22em 宽字距。英文字母本身有字间节奏，再加宽字距，就显得散而挤；标题只有 20px，撑不起首屏。
- 已改：英文正文与界面字换成 **Instrument Sans**（SIL OFL，自托管拉丁子集 37KB），字号令牌整体上调一档，英文统一回到正常字距；英文标题继续用 Bodoni Moda 并放大、字距收紧（D72 起全站改为无衬线，见 §七）。
- 首页第二部分原来是 10 行与轮播完全重复的衣橱列表，不产生任何行动。换成 **「按场合，整套穿走」**：按场合切换，每个场合一套主推（大图 + 逐件单品、价格、一键试穿 + 整套加入试衣间 / 购物袋），再加同场合的另外三套。
- 衣橱列表没有消失，变成独立的 **全部衣橱目录页 `/closets`**：网格 + 性别、衣橱类型、风格筛选，筛选写进网址；导航“衣橱”指向它，首页轮播下方也有入口。
- 导航新增“搭配”（锚点到首页新区块）与“搜索 / 问造型师”（打开悬浮对话），主链接与工具图标之间加细分隔线。
- 线上验证记录的 8 处英文排版问题：同期 PR #28 已修好并上线，本分支合并 main 时以它的写法为准（第 1 处随旧列表移除）；本分支补了它没覆盖的衣橱页卡片列宽（换字体后的防溢出）与几处字距。

## 二、首页第二部分该放什么

### 回看项目目标

- 定位（PRD §1）：主理人和品牌策展、AI 帮助搭配的大众时尚平台——发现审美，把服装带进个人试衣间，以自己的形象查看，再完成可信选购。
- 用户定的核心亮点（D67）：“浏览的过程中，可以直接一键试穿……一键试穿应该非常明显的功能入口”；平台主打（D59）：用本人形象试穿并判断合身；站内下单（D57）。
- 首页（F01）：浅弧主卡保留，扩展五类发现入口；AI 对话负责帮用户定位（D52、D66）。
- 商业模式（商业模式与平台运营 §1）：长期收益取决于复访与净成交，“不取决于衣橱数量本身”。

### 原列表的问题

首屏轮播已经回答了“走进谁的衣橱”。第二部分再列一遍同样的 10 间衣橱，用户往下滑只看到重复信息；没有价格、单品，也不能试穿或加入试衣间，离成交还隔着“进衣橱 → 选搭配”两步。

### 候选与取舍

| 候选 | 为什么不选 / 为什么选 |
| --- | --- |
| 新品单品网格 | 单品是零散的，SEEN. 的独特价值是“主理人搭好的整套”，单品网格与普通电商无异 |
| 主理人 / 衣橱列表（原方案） | 与首屏轮播重复；保留到 `/closets` 目录页并提供筛选 |
| 品牌墙 / 合作方 | 目前没有真实品牌合作，不能虚构供给（PRD §1.1） |
| 数字分身推广横幅 | 是主打能力，但单独一块横幅不产生购买行动；本次把“试穿”放进每件单品上，横幅留作后续 |
| **按场合整套（选用）** | 对应用户最直接的需求“我明天需要穿什么”（PRD §1.1）；整套是 SEEN. 的核心单位；每件单品就地一键试穿（D67）、整套加入试衣间 / 购物袋（D57、D67），一屏完成从看到试到买；场合也是 AI 对话的主要线索，区块右上角直接接“问造型师” |

结构参考 Zara 首页的 “LOOK · N items” 模块（大图 + 一排单品，每件带价格与操作），视觉沿用 SEEN. 自己的深色玻璃系统。

### 实现

- 场合：周末、通勤、约会、聚会、旅行、婚礼宾客（目录 v0.2 里搭配最多、最贴近日常的六个，中文原值，显示时翻译）。
- 每个场合最多 4 套：在主理人之间轮流挑，同一间衣橱不连着出现；各场合的主推不重复（`lib/home/edit.ts`，4 项测试）。
- 一键试穿与加入试衣间复用衣橱页的 `QuickTryButton`、`LookActions`，行为一致；本地没有 `FAL_KEY` 时试穿按钮不显示（与衣橱页相同）。
- 键盘：场合标签按 WAI-ARIA tabs 实现，左右方向键、Home / End 切换。

### 衣橱列表去哪了：`/closets`

- 网格展示全部衣橱（手机两列、宽屏三列）：场景图、主理人头像、类型、衣橱名、简介、搭配数、风格。
- 筛选：性别 × 衣橱类型（F01 五类发现入口）一行，风格一行；组合后没有结果的选项置灰；条件写进网址（`?gender=男装&style=极简`），刷新、分享、返回都能还原。
- 入口：导航“衣橱”（衣橱页、搭配页也算这一栏）；首页轮播下方“查看全部 10 间衣橱”。首页原有的筛选保留，只作用于轮播。

## 三、导航

- 主链接：衣橱（→ `/closets`）· 搭配（→ 首页 `#looks`）· 试衣间 · 我的档案 / 登录。
- 工具：搜索 / 问造型师（打开悬浮对话，≥900px 显示；手机右下角常驻对话入口）· 购物袋 · 语言 · 主题，与主链接之间加 .5px 分隔线。
- 宽度沿用首页宽栏（与中央卡片对齐）；640–899px 收窄链接内边距。实测 640、768、900、1024、1280px 中英文都不溢出。

## 四、参考与决策

参考（Refero）：SSENSE、FARFETCH、Sneak in Peace 的完整风格规范；Zara 首页 “LOOK” 模块、SSENSE 首页的实际页面。

参考锁定：

- 主方向：SEEN. 现有视觉系统（视觉规范 v5）——深色电影感背景与环境场景、玻璃面板、香槟金只用于主操作、金箔只用于编号与总价、Bodoni 标题（D72 起改为全站无衬线）。
- 借用：Zara 的整套模块结构；SSENSE 的字体对比（大号衬线标题字距收紧 + 正常字距的实用型无衬线小字）与 64–112px 的区块间距。
- 不采用：参考站的白底、直角零圆角（与 SEEN. 的玻璃系统冲突）；英文宽字距；十行相同的列表。

| 决定 | 来源 | 理由 |
| --- | --- | --- |
| 英文界面字 Instrument Sans 400/500 | SSENSE、Sneak in Peace、FARFETCH 都用正常字距的怪诞体做界面字 | 与 Bodoni 标题形成对比，小字号清晰 |
| 英文字距 0–.02em，小号大写 .06em | 同上；字体排印常规 | 英文字母自带间距，宽字距只适合全大写短标签 |
| 首屏标题 24/28px、区块标题 32/42px | SSENSE 标题 38–56px | 首屏要给轮播留高度，所以首屏标题只放大一档，区块标题放开 |
| 区块间距 72 / 112px | SSENSE 64px、FARFETCH 48–72px | 首页两部分分清层次 |
| 整套模块：大图 + 逐件单品 + 总价 + 整套操作 | Zara “LOOK” 模块 | 整套是 SEEN. 的核心单位，一屏完成看、试、加入 |
| 场合标签：文字 + 细下划线 | FARFETCH 分类条 | 低装饰，手机可横滑 |
| 香槟金只给“整套加入试衣间”，金箔只给总价 | SEEN. 视觉规范 | 保持主操作唯一 |

## 七、字体统一（D72 · 2026-10-25）

依据：用户 2026-10-25 原话“还需要针对字体做修复。既然你已经在采用无衬线的字体了，那就统一风格。而且这是一个 digital product。……你应该从顶级的 Digital Product UI Designer，字体设计师，以及时尚产品设计师的角度去思考和提案。……中英文的字体选择你都需要考虑。”

### 结论

- 西文与数字一律 **Instrument Sans**，汉字一律**思源黑体**（正文 Light 300，标题 Medium 500）。全站不再出现衬线字和斜体，也不合成粗体、斜体。
- 层级只用四个变量：字号、字重、字距、大小写。价格、编号、计数用等宽数字。
- 中文首页的字体下载从 27 个文件、约 1.99MB 降到 3 个、约 491KB；英文首页从 6 个、435KB 变为 3 个、491KB（多出的是标题里汉字人名用的 Medium）。

### 为什么要统一

| 角度 | 判断 |
| --- | --- |
| 数字产品 UI | 这是天天被使用的工具：同一屏里有导航、筛选、标题、价格、按钮。原来一屏同时出现衬线标题、无衬线界面字、斜体引题三种“声音”，层级靠换字体而不是靠尺寸和字重，扫读变慢；Bodoni 的细笔画在 11–15px 小于 1px，深色背景上发虚。统一字族后组件规则可预测，深浅主题、中英文的表现一致。 |
| 字体设计 | 配对看骨架、字重和灰度，不看风格名。思源黑体 Light 自带的西文与汉字同一字重，适合中文正文；标题用思源黑体 Medium 配 Instrument Sans 500，两种文字的笔画灰度接近。只用字体文件里真实存在的字重：原来 400 以上的中文是浏览器把 Light 描粗（伪粗体），斜体是把字形斜切（伪斜体，汉字没有斜体）。中文的弯引号、破折号、省略号保留全角字形，不让西文字体接管。字距：汉字标题 .04em，西文标题收紧到 −.015em，全大写小标签放开到 .12–.14em。 |
| 时尚产品 | 时装电商的高级感来自克制、留白、摄影与一致性，而不是衬线：COS 全站只用一款 SuisseIntl，靠字重与字号分层；SSENSE、FARFETCH 的界面全部是无衬线，品牌名用全大写小字。SEEN. 的字标本身就是无衬线的高反差字标（`docs/宣传/logo/seen-logo.js`），衬线标题是 v4 杂志样稿留下来的，反而和品牌标识不一致。品牌情绪交给场景摄影、灯光、香槟金与字标。 |

### 候选与取舍

| 用途 | 候选 | 结论 |
| --- | --- | --- |
| 汉字 | 思源黑体、阿里巴巴普惠体、HarmonyOS Sans、系统苹方 | **思源黑体**：SIL OFL，可以自托管、做子集（D50 的约束），字重 100–900 齐全，正文已在用。普惠体与 HarmonyOS Sans 不是 OFL，再分发与子集化要逐条核对许可；苹方不能自托管，Windows、Android 上会回退成别的字体。 |
| 西文 | Instrument Sans、Inter、Geist | **Instrument Sans**（D71 已引入）：怪诞体骨架，比 Inter 更有时装感、比 Geist 柔和；可变字重 400–700，带等宽数字（tnum）与大写标点（case）。 |
| 标题字重 | Regular、Medium、SemiBold | **Medium 500**：深色背景上 Regular 与正文分不开，SemiBold 以上和玻璃面板的轻盈不搭。 |
| 引题 | 斜体、全大写加字距 | **全大写 + 字距**：无衬线体系里的标签做法，不需要斜体。 |
| 中文正文 | Light 300、Regular 400 | **保留 Light 300**（D50 用户要的“呼吸感”），不在本次重开。 |

### 规格

完整规格见[视觉规范 §5](../design/visual-v04/视觉规范.md)。令牌在 `app/app/tokens.css`：`--sc-font-sans`（正文）、`--sc-font-display`（标题，配 500）、`--sc-font-label`（引题、编号、价格），`--sc-track-display`（中文 .04em / 英文 −.015em）、`--sc-track-title`（.03em / 0）；英文取值在 `globals.css` 的 `html[lang="en"]`。

### 改动

- 字体文件：思源黑体子集按当前文案重新生成为 v2，新增 Medium 500 一套（core / 一级 / 二级，按 unicode-range 按需下载），`scripts/build-fonts.py` 一次生成两个字重；删除 `app/fonts-serif.css` 与 `public/fonts/serif/`（Bodoni Moda、思源宋体，共 204 个文件、约 12MB）。
- `app/fonts-latin.css` 增加别名 “SC Latin”（同一个 Instrument Sans 文件，去掉弯引号、破折号、省略号），供中文页面的标题与标签使用。
- 样式：`tokens.css`、`globals.css` 与 11 个组件样式里约 60 处衬线 / Didone / 斜体改为上面的三个角色；为 Bodoni 调的英文字号（32–42px）重新按 Instrument Sans 调小（28–36px）；`serif-note` 类改名为 `note-text`。
- 全大写标签统一 11px：里面常有中文人名和衣橱类型，10px 的汉字太小。

## 八、编辑大字（D73 · 2026-10-25）

依据：用户 2026-10-25 原话“英文字体选用上，我刚才看了 Farfetch，COS，他们的英文采用了很多 All Captical。并且他们也是没有采用衬线字体，并且跟干净利落的笔触。我猜想可能是他们的布局本身就很有呼吸感……我们不需要按照一般中国电商的设计，弄得很紧凑。……给我多个方案的截图或者预览。”看过方案后回复：“用 B 编辑大字的方向，在 PR #27 上落地。”

### 探索

在 `explore/type-layout` 分支用 cookie 切换三个方案，颜色、玻璃、圆角、图片都不变，只改字体与布局：

| 方案 | 字体 | 全大写 | 布局 |
| --- | --- | --- | --- |
| A 克制大写（参考 COS） | 西文 Geist | 导航、区块标题、标签页、筛选、按钮；标题字号克制 | 留白 |
| **B 编辑大字（参考 SSENSE，选用）** | 大标题 Instrument Sans 半窄体；中文大标题思源黑体 Light | 导航、所有大标题、标签页、筛选、按钮 | 编辑式：手机一行一张大图 |
| C 只加留白（对照） | 不变 | 不变 | 与 A 相同的留白 |

参考（Refero）：COS（全站一款无衬线、导航全大写、字重分层）、FARFETCH（48–72px 区块间距、宽松网格）、SSENSE（全大写大标题与小号大写导航）、YSL（暗场、全大写小字）。西文候选字样对比了 Instrument Sans、它的半窄体、Geist、Host Grotesk、Hanken Grotesk 与 Inter，全部 SIL OFL。

### 落地规格

完整规格见[视觉规范 §5](../design/visual-v04/视觉规范.md)。要点：

- **大标题**：全大写、Instrument Sans 半窄体 500（宽度轴固定 82，自托管拉丁子集 37KB），行高 .92–.95；中文大标题用思源黑体 Light 300 放大。首页与目录区块标题 46 / 88px（英文，手机 / 桌面）、34 / 52px（中文）；衣橱页衣橱名 52 / 96px、40 / 64px；页面标题 40 / 64px、34 / 48px。
- **全大写**：导航（英文 11px、字距 .1em）、按钮（12px、.1em）、标签页与筛选（11–12px、.08–.1em）、区块标题与小链接。衣橱、搭配、单品名称保持原大小写。
- **小字号**：16px 以下的名称（对话卡片、语言菜单、单品页相关搭配名）用常规宽度，半窄体在小字号下难读。
- **留白**：手机左右留白 22px；首页两区块间距 136 / 200px；主推卡片内边距 32 / 56px；首页同场合的其他几套、全部衣橱目录在手机上一行一张大图；宽屏目录两列、衣橱页搭配网格两列。
- 全大写后「Add look to Fitting Room」变宽，卡片宽度 440px 以下时两个整套按钮上下排。
- 档案页英文引题由 “My Profile” 改为 “The Profile”，不再和标题重复，与 “The Fitting Room”“The Bag” 一致。
