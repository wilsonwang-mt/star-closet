### 项目 Owner 的实施决定（17:30）

- 演示入口：先选主理人的一套搭配，再用一句话改编；首页不做自由需求入口。
- 模型：Claude Opus 5.5，effort `low`，配等待动画；周五实测延迟，超过 10 秒再评估。
- 设备：手机优先，宽屏自动并排对比；加 PWA 配置。

- 先用标注“占位”的数据开发，顾问数据到位后替换。3D 与试穿在核心层跑通前不做。

## 0. 一页结论

1. **我们有一份精致的方案，没有产品。** 约 38 万字节文档、26 页 Slides、0 行应用代码；距周六 12:00 截止还有 44 小时。今天评审，Demo 项接近 0 分。
2. **最大阻塞是编码授权，不是技术。** 冲刺 G0（13:00）、G1（15:00）均已逾期，17:00 的 3D 门槛按现状必然失败。授权一到，44 小时足够做出一条可信的闭环。
3. **定位要从“平台全景”收敛到一个楔子：把主理人的一整套穿搭，改编成适合我、买得起、能上身的一整套。** 单纯“截图试穿”已有 Google Doppl、淘宝千问、Zara 等在做，不是差异点；“策展整套 × 本人约束改编”才是空位。
4. **供给就是我们的时尚顾问。** 她是第一位主理人，用“风格主题”衣橱，不用明星入口；商品挂公开可购链接，只做导购。
5. **比赛版演示分三层**：核心层只依赖 LLM，今晚必达；2D 试穿与一件可旋转 GLB 是加分层，取决于发起人今晚能否开通试穿服务、拿到许可明确的模型。

## 3. 比赛版：三层演示

### 3.1 核心层（今晚必达，只依赖 LLM API key）

顾问策展的衣橱（6–8 套搭配、30–40 件单品，含图片、价格、购买链接）→ 用户选中一套 → 用一句话改约束（例：“预算 800 以内，换成平底鞋，场合是户外婚礼”）→ AI 在目录内改编成新的一整套，逐件说明理由与总价 → 用户可替换单品 → 加入个人试衣间 → 外链购买。

验收：AI 只返回目录内的商品；总价与预算对得上；超预算或缺品时明确告知；文字输入可用，语音输入为增强。

### 3.2 加分层 1：2D 试穿（需发起人今晚开通试穿服务并提供 key）

在试衣间里对改编后的整套生成“穿在我身上”的 2D 预览，与原版对比。候选服务 FASHN `tryon-v1.6`（官方 $0.075/张，最低充值 $7.50），备选 Google Vertex `virtual-try-on-001`。照片只用已同意的队员或合成人物，不进仓库。

界面固定显示三枚徽章：「2D 生成预览」「非本人 3D 模型」「合身：未验证」。授权后 4 小时内打通一次真实调用，并录下真实结果作为“预录”兜底。

### 3.3 加分层 2：一件可旋转 GLB（需许可明确的模型，及发起人同意 D11 比赛版降级）

商品详情里一件服饰在聚光下真实旋转，作为视觉签名。首选 Khronos MaterialsVariantsShoe（CC-BY-4.0）；其他候选需人工下载并逐件核许可。授权后 6 小时内没有合格模型，就放弃这一层。

### 3.4 90 秒演示脚本

1. （10 秒）痛点：收藏了一百套穿搭，还是不知道自己该穿什么。
2. （15 秒）打开顾问的衣橱，暗色玻璃陈列，选中一套喜欢的搭配。
3. （25 秒）说一句“预算 800，户外婚礼，换平底鞋”，AI 改编出新的一整套，逐件解释。
4. （20 秒）放进试衣间，看到穿在自己身上的样子（加分层 1），一件鞋可旋转查看（加分层 2）。
5. （10 秒）外链购买；顾问获得佣金。
6. （10 秒）愿景：让每一种喜欢的风格，都能穿到自己身上；未来一页带过建橱 Agent、本人 3D、主理人生态。

## 4. 技术路线

- **框架：Next.js（App Router）+ TypeScript。** 理由只有一条：LLM 与试穿服务的 key 必须留在服务端，Next.js 的 API Route 自带服务端；Vite 需要另起后端。
- **AI：** Claude API 结构化输出，整份目录 JSON 放进 prompt，返回 `{items: [item_id], reasons, total}`；服务端校验所有 ID 都在目录内，否则重试或请用户澄清。不用向量库。
- **语音：** 浏览器 Web Speech API，识别文本可编辑；文字输入始终可用。
- **3D：** R3F 只作为详情卡内的单个组件，不做整屋场景。
- **数据：** 静态目录 JSON + 浏览器本地试衣间状态；无数据库、无账号、无支付。
- **部署：** 演示需要一个可访问的 URL；Vercel 部署需发起人另行授权（§7④）。
