## 与任务单的差异（请指挥台确认）

1. **`scene_render` 多一列 `video_status_url`**：保存 fal queue 的状态查询地址，服务重启后仍能继续轮询；视频完成或失败后清空。任务单列出的字段都保留。
2. **新增视频路由 `/api/scene/video/[id]`**：现有 `/api/avatar/files/[...key]` 不支持 Range，iOS Safari 播放视频需要 Range；那个路由不在 T3 可改范围，所以另写了一个，只读本人的 `scene_render.video_key`。
3. **同意沿用 `tryon_consent`**（按任务单），但它的版本号是 `tryon-consent-v1:fashn_fal`、原文写的是“发送给 FASHN（fal.ai）生成试穿图”。上身效果用的是 fal 上的 nano-banana-pro 与 Kling，详情页勾选框文案写成“同意把我的正面照发送给 fal.ai 生成上身效果图”。两处文案不同、记录相同，是否需要单独一项同意，由指挥台决定。
4. **`globals.css` 不在可改范围**：两个新链接的样式用内联写法。

## 遗留问题

1. **一般｜本人 Live 视频体积大**：Kling 原始输出约 1080p、14–17MB/段，没有服务端转码（本机无 ffmpeg，生产环境也未必有）。首次悬停在弱网下要等较久才开始播。可考虑改用输出分辨率更低的模型，或在有转码能力的环境压到 720p。
2. **一般｜同意文案与记录不一致**（见上文差异 3）。
3. **体验｜本人场景图 1.4–1.6MB/张**（2K JPEG 原样保存）。画廊显示正常，但可以再压缩。
4. **体验｜生成约 30 秒只有等待卡和秒数**，没有进度；两张图同时出现。
5. Supabase 需要指挥台执行：`npm run db:setup`（迁移 0004）后再执行一次 `supabase/rls.sql`。在此之前，详情页的“上身效果”查询失败时会退回演示模特画廊、不显示生成入口（页面仍是 200，服务端日志记一行 `[scene]`）；`/api/scene` 会返回 500。
6. 未在实体手机上测试（长按与震动用 CDP 模拟）；没有测 60fps。
