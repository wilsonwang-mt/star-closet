## 2. 共同设计原则

1. 第一眼知道当前是谁的衣橱，第二眼找到搜索、切换与进入。
2. 衣橱是视觉主体；头像负责身份识别，不盖过空间本身。
3. 玻璃组织信息和层次；衣橱画面、服饰纹理与文字保持清晰。
4. 未来感来自精确材质、自然光影、空间秩序与可预测的运动。
5. 衣服真实感依赖几何、布料厚度、接缝、贴图、光照和观察距离的共同质量。
6. 平台界面统一，各衣橱保留自己的色温、陈列和审美特征。
7. 搜索与列表是完整入口，用户不必在三维轮播中逐个寻找。
8. 复杂度用于表达空间和内容，避免霓虹、漂浮装饰与大量发光标签。

暗背景不能只靠黑色投影体现深度，还需要接触阴影、边缘高光、透视和遮挡。
所有探索方向都遵守 VD01—VD09；差异是空间表达与内容重心，不只是换配色。

## 3. 方向 A：悬浮衣橱画廊

核心：像在安静的夜间建筑展厅中，选择一间精致的微缩衣橱。
预览采用切开式空间构图，看到地面、墙面、陈设与服饰之间的关系。
中央正对，左右浅透视退后；玻璃信息底座承接人物身份、风格和进入按钮。
房内可以温暖，外部舞台保持冷静，环境反射把房间与平台联系起来。
单品聚焦仍保留原房间的环境线索，避免从空间突然跳到无关商品弹窗。
优势：房间结构容易比较；特色可以记忆；符合用户确认的卡片与空间关系。
风险：微缩房间可能像玩具；墙体切口、服装尺度和布料细节需精细处理。
验证问题：用户能否理解它可以进入，而不是一张建筑展示图？
建议先用一间房间和一件完整服饰检验质感，不以数量掩盖资产问题。
状态：推荐优先探索，未获用户批准为最终方向。

## 4. 方向 B：夜间时尚档案

核心：像阅读一本可以走进去的时尚档案，先理解人物的审美和服饰故事。
预览采用眼平视角，空间接近真实居住尺度，强调陈列、光线与生活气氛。
依然使用浅弧卡片，每张像一扇宽大的烟灰玻璃展窗，减少模型底座感。
搜索和编辑内容更明显，姓名、风格与有证据支持的收藏线索形成阅读层级。
详情页中，材质观察与穿着故事并重，长内容展开后阅读。
优势：搜索与阅读空间充分；内容扩展自然；真实尺度更容易产生代入感。
风险：空间结构不如切开式全景清楚，也容易退化成普通图片轮播。
验证问题：用户是否知道卡片后面有可探索的空间，而不是一篇文章？
状态：与方向 A 并列比较，尚未选择。

## 5. 方向 C：光场展厅

核心：站在深色展厅里，沿浅弧排列的空间入口选择下一站。
每张卡像有实体边界的玻璃入口，能看到真人尺度衣橱的纵深。
深度来自入口位置、地面接触阴影和房内透视，避免变成不断旋转的隧道。
进入按钮仍在信息区，不能只依赖用户理解门户隐喻。
点击后，外框逐步退出，镜头沿安全路径进入房间，形成连续体验。
优势：从首页到衣橱再到服饰的空间衔接有辨识度。
风险：镜头与资源协同复杂，长转场可能妨碍搜索直达用户，也更容易引发眩晕。
验证问题：正常动画、减弱动态和资源未就绪时，是否都能快速进入并返回？
状态：作为转场研究，不先承诺完整实现。

## 6. 概念比较与选择方法

| 维度 | A 悬浮衣橱画廊 | B 夜间时尚档案 | C 光场展厅 |
| --- | --- | --- | --- |
| 主体 | 微缩空间全貌 | 人物审美与房间取景 | 房间入口与空间纵深 |
| 发现重心 | 空间特色 | 搜索和编辑内容 | 空间选择与探索 |
| 手机重点 | 轮廓清楚，细节需检验 | 信息易读，需强化空间暗示 | 入口明确，横屏价值明显 |
| 素材依赖 | 完整房间结构与尺度 | 高质量取景与资料 | 连续空间与镜头路径 |
| 主要风险 | 玩具感 | 像摄影文章站 | 沉浸妨碍效率 |

用同一组虚构内容、尽量一致的材质和光照比较构图，避免把素材差异当成布局优劣。
先比较 A/B，再研究 C 的转场；不同时混用三套视觉语言。

## 7. 桌面首页与导航

导航需容纳品牌标识、衣橱发现与明显的搜索入口；最终命名以产品信息架构为准。
收藏、账号等额外入口仍是功能建议，不能因为生成图出现图标就认为已经批准。
首屏避免长宣传文案，把面积留给衣橱、身份信息和操作线索。
中央卡片占主要视觉面积，侧卡露出部分足以辨认下一项；文字与按钮保持稳定正面。
头像、姓名、风格和进入按钮处于同一信息底座，阅读顺序一致。
建议点击侧卡先选中，点击当前卡的进入按钮再进入；此规则仍需验证误触成本。
方向按钮提供拖动之外的方式；位置提示不单独承担切换功能。
默认不自动轮换，避免阅读或即将点击时目标移动。
下方可探索按风格、品牌、类别或继续查看等模块，数量以真实内容供给决定。

## 8. 搜索与发现

搜索完整覆盖姓名、风格、标签、品牌、服饰类别，不藏进深层菜单。
搜索结果采用稳定列表或网格，不能仍要求用户逐个旋转三维轮播。
人物、衣橱、服饰和品牌结果需有类型标签与明确点击去向。
显示可理解的筛选、排序、选中条件与清除操作；数量必须来自真实数据。
无结果时保留关键词，提供修改条件或相近类别入口。
慢加载时使用与真实内容结构相近的占位，不用无限旋转装饰模型代替反馈。
搜索直达服饰后，仍能看到所属衣橱、来源和返回路径。
房间没加载完不应阻止先阅读详情；列表延续材质语言，但减少重光影和大范围模糊。

## 9. 衣橱内部

场景是主体，导航和操作采用少量固定锚点，避免悬浮控件铺满画面。
保留人物身份、退出、查找服饰和操作帮助；可点服饰提示应克制且可关闭。
首次简短提示点击服饰，完成一次后不反复打断。
镜头建议少量明确位置；是否自由漫游另作交互与性能验证。
返回时恢复原来的浏览位置和相关服饰附近视角，不重置到入口。
布景和可检视服饰不能完全使用相同交互暗示；物件多时可提供辅助清单。
加载失败时给出重试、返回与静态浏览路径，不能把用户困在黑色场景里。

## 10. 服饰聚焦与右侧玻璃卡

选中后镜头靠近、环境适度压暗、射灯建立中央舞台，原衣橱仍能辨认。
服饰优先完整可见，再提供局部细节；保留穿着体积、厚度和自然垂坠。
射灯聚焦，柔和补光保留暗部，轮廓光帮助深色衣服从背景分离。
灯光保持空间方向，衣服旋转时高光与阴影自然变化。
桌面建议服饰占主要面积，右卡约占可用宽度四分之一至三分之一。
卡片背景半透明且适量模糊，文字、图标和焦点轮廓始终锐利。
先显示所属衣橱、名称、品牌、材质摘要、故事摘要与主要操作，长内容分组展开。
详情维度应覆盖版型、尺寸与尺码、颜色、材质、护理、来源关系、商家和购买规则。
原件、同款新品、相似款必须明确区分，不能暗示商品就是本人穿过的那件。
购物模式仍待决策；按钮随真实能力显示外跳、平台下单或不可售，不能提前作承诺。
价格、库存、运费、销售方、履约方和退换条件必须有可核验来源。
暖色聚光会影响衣色判断，建议验证中性检视光或实拍细节入口。

## 11. 旋转与素材真实性

默认拖动旋转，提供可见复位以及非拖动替代操作，不要求用户猜手势。
建议水平可完整查看，垂直角度与缩放边界按模型、构图和设备验证。
服饰不默认持续自转；停止操作后能安静观察纹理和文字。
旋转衣服不带动整个房间旋转；放大后能方便返回整体视图。
鼠标、触摸、键盘应能完成主要角度查看与复位，实际实现后验证。
只有完整模型可以标记为真实可旋转 3D；照片组和 360 图片序列要准确标示形式。
模型对应具体款式与颜色；未制作变体不能被示意模型暗示为已有三维素材。
单张概念图不能证明背面、接缝、内衬或旋转质量，也不是 GLB 文件。

## 12. 手机竖屏与横屏

首页默认竖屏挑选，中央一张为主、两侧露出邻项，不直接缩小桌面三列布局。
姓名、风格与进入按钮不依赖悬停；侧卡避免放独立小按钮。
区分横向切换和网页纵向滚动，轻微斜拖不应立刻抢占手势。
键盘弹出、地址栏变化、字体放大和安全区都需纳入版式检查。
进入具体衣橱前提醒横握；已经横屏时不重复打断。
建议文案：“建议横握手机，获得更宽阔的衣橱视野。”
“继续竖屏浏览”是待验证建议；网页方向锁定受浏览器限制，不能作为依赖。
横屏手机高度有限：服饰在左，信息在右，导航只保留必要控件。
右卡先给摘要和操作，再展开长内容，并允许暂时收起以看清服饰。
旋转设备时保留当前衣橱、服饰和浏览状态，避免从头加载。
若保留竖屏检视，建议服饰在上、信息为底部抽屉或正常内容区。
品牌说明、地址表单与购物规则优先稳定二维阅读，不强制横屏。

## 13. 灯光、材质与渲染策略

| 对象 | 视觉意图 | 待验证问题 |
| --- | --- | --- |
| 背景 | 深而有层次，保留环境反射 | 手机低亮度下是否丢失层次 |
| 玻璃 | 烟灰半透明、边缘高光和厚度 | 不透明降级后是否仍清楚 |
| 布料 | 纤维、褶皱、厚度与粗糙度可信 | 近看是否暴露贴图或网格不足 |
| 金属 | 反射具有环境依据 | 多角度下是否稳定，是否过曝 |
| 舞台 | 接触阴影与低强度反射落地 | 是否漂浮、过黑或锯齿明显 |
| 房间 | 主光、补光、反射共同解释空间 | 镜头变化后是否仍可信 |

复杂光影可由烘焙环境、少量实时灯光和合适贴图共同实现，具体路线尚未选择。
首页可比较渲染预览与当前项渐进增强，不同时加载所有完整房间。
预览和内部模型保持同一陈设，避免像进入另一间房。
玻璃模糊面积、透明叠层和动态反射需要性能预算，不能只凭截图决定。
不同设备可降级渲染，但形状、颜色与商品信息含义应一致。

## 14. 动效分镜

| 过程 | 动作意图 | 候选时长，不是已测结果 |
| --- | --- | --- |
| 首屏出现 | 先可读，再建立轻微深度 | 约 300—600 毫秒 |
| 切换衣橱 | 中央后退、相邻项来到中央 | 约 300—500 毫秒 |
| 进入 | 从预览延续到同一房间 | 约 500—900 毫秒 |
| 聚焦 | 靠近、压暗、建立聚光 | 约 350—650 毫秒 |
| 信息卡 | 与聚焦重叠出现，不串行等待 | 按可读性验证 |
| 返回 | 收卡、恢复光线与来源视角 | 不长于进入 |

允许中断、反向操作和快速返回，不在动画期间禁用所有按钮。
避免镜头、缩放和背景同时大幅运动，也不把长距离飞行设为必经步骤。
减弱动态时移除空间飞行与视差，以短淡入或直接切换表达同一状态。

## 15. 状态与失败路径

| 页面 | 必须设计的状态 | 保留的操作 |
| --- | --- | --- |
| 首页 | 当前项、拖动、切换、加载、失败、键盘焦点 | 搜索、切换、重试 |
| 搜索 | 输入、建议、筛选、加载、无结果、错误 | 修改条件、清除、返回 |
| 衣橱 | 资源准备、浏览、聚焦过渡、返回、失败 | 返回、重试、静态浏览 |
| 服饰 | 整体、旋转、放大、复位、无完整模型 | 看详情、切换准确的展示形式 |
| 购物 | 可售、不可售、状态未知、外跳或站内模式 | 看规则，不作假库存承诺 |
| 手机 | 竖屏首页、横屏提示、横屏检视、旋转途中 | 保留当前位置与退出方式 |

失败提示说清当前受影响内容，不用无限加载掩盖失败，也不自动丢弃用户选择。

## 16. 可读性、可访问性与候选 token

普通文字对比度目标至少 4.5:1，大字与必要图形按相应标准检查，尚未实测。
在最亮、最暗衣橱背景上验证，而非只看统一底色截图。
重要触摸目标建议至少 44 CSS 像素并留间距；焦点可见，抽屉有合理关闭与焦点管理。
轮播提供上一项、下一项和位置语义，隐藏侧卡不制造焦点陷阱。
颜色或发光不单独承载选中、错误或可购买状态。
WebGL、模型或模糊效果不可用时，使用有说明的静态素材和更实的烟灰信息底色。
